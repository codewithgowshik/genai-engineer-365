# Day 136 — Score Answer Faithfulness with an LLM Judge

**Phase:** 4 — Retrieval-Augmented Generation (RAG)  
**Week:** 20 — RAG Evaluation  
**Learn:** Faithfulness and answer relevance  
**Build:** Score answer faithfulness with an LLM judge

## 1. What is faithfulness?

Faithfulness measures whether an answer's claims are supported by the retrieved context.

Example context:

> Python is a programming language created by Guido van Rossum.

Faithful answer:

> Python is a programming language created by Guido van Rossum.

Potentially unfaithful answer:

> Python is a programming language created by Guido van Rossum in 1995, and it was originally developed at Google.

The extra claims are not supported by the context. **Unsupported does not automatically mean false; it means the provided evidence does not establish the claim.**

## 2. What is answer relevance?

Answer relevance measures whether the answer addresses the user's question.

Question:

> What is a vector database?

Irrelevant answer:

> Python is a popular programming language.

Relevant answer:

> A vector database stores and searches vector embeddings, helping applications find information based on similarity.

### Faithfulness vs. answer relevance

| Metric | What it measures | Key question |
|---|---|---|
| Faithfulness | Whether the answer is supported by retrieved context | Is the answer supported by the evidence? |
| Answer relevance | Whether the answer addresses the question | Does the answer answer the question? |

An answer can be faithful but irrelevant, or relevant but include unsupported claims. A useful RAG answer should aim to be both faithful and relevant.

## 3. What is an LLM judge?

An LLM judge is a language model used to evaluate another model's output.

Give the judge:
1. The original question.
2. The retrieved context.
3. The generated answer.

Ask it to assess whether the answer's claims are supported by the context and provide a score with a short explanation.

An LLM judge is not guaranteed to be correct. It can miss unsupported claims or judge inconsistently, so treat its scores as estimates rather than ground truth.

## 4. A simple faithfulness scoring rubric

This is a custom rubric for this learning experiment, not a universal standard.

| Score | Meaning |
|---|---|
| 1.0 | All claims are supported by the retrieved context |
| 0.5 | Some claims are supported, but others are unsupported |
| 0.0 | The answer is largely unsupported by the retrieved context |

Example context:

> ChromaDB is a vector database used to store and retrieve embeddings.

Example answer:

> ChromaDB is a vector database used to store embeddings, and it was created in 2010.

The context supports the first claim but does not support the creation date. A judge should flag the unsupported claim.

## 5. Where the judge fits in the RAG pipeline

```text
User question
    |
    v
Retrieve relevant documents
    |
    v
Retrieved context
    |
    v
LLM generates an answer
    |
    v
Generated answer
    |
    v
LLM judge evaluates the answer
    |
    v
Faithfulness score + explanation
```

Retrieval evaluation asks whether the system found relevant information. Faithfulness evaluation asks whether the generated answer stays grounded in that information.

## 6. Today's build

Create a new file:

```text
src/evaluate_faithfulness.py
```

The experiment should:
1. Define a test question.
2. Retrieve relevant documents using your existing retrieval function.
3. Generate an answer using your existing LLM functionality.
4. Send the question, retrieved context, and generated answer to an LLM judge.
5. Ask the judge for a faithfulness score and brief explanation.
6. Print the question, context, generated answer, score, and explanation.

Illustrative output (not a measured result):

```text
Question:
What is a vector database?

Generated answer:
A vector database stores and searches vector embeddings.

Faithfulness score:
1.0

Explanation:
The answer is supported by the retrieved context.
```

Start with one question, confirm the experiment works, and then test several examples. Include both answers supported by context and answers containing unsupported claims.

## Key takeaways

- **Faithfulness:** Are the answer's claims supported by retrieved context?
- **Answer relevance:** Does the answer address the question?
- **LLM judge:** A model that estimates answer quality using an evaluation prompt.
- **Important limitation:** Judge scores are estimates; validate them with test examples and human review where possible.
