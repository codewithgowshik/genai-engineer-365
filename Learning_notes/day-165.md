# 1. What Is Instruction Tuning?

Instruction tuning is a process of training an already-pretrained language model using examples of instructions and their expected responses.

The purpose is to teach the model how to follow human instructions more effectively.

### Example

**Instruction:**
Explain what Artificial Intelligence is.

**Expected Output:**
Artificial Intelligence is a field of computer science that develops machines capable of performing tasks that normally require human intelligence.

By learning from many instruction-response examples, the model becomes better at understanding and following instructions.

### Pretraining vs Instruction Tuning

| Pretraining | Instruction Tuning |
|---|---|
| Learns general language patterns | Learns to follow instructions |
| Uses large text datasets | Uses instruction-response datasets |
| Develops general language capabilities | Improves task-oriented responses |
| Usually happens first | Usually happens after pretraining |

**Important:** Instruction tuning does not mean building a model from scratch. It adapts an existing pretrained model.

# 2. What Is Supervised Fine-Tuning (SFT)?

Supervised Fine-Tuning (SFT) is a training approach that uses examples containing inputs and desired outputs.

The model learns by comparing its generated responses with the expected responses.

### Example Dataset

```json
{
  "instruction": "What is Python?",
  "input": "",
  "output": "Python is a high-level programming language."
}
```

Another example:

```json
{
  "instruction": "Explain machine learning.",
  "input": "",
  "output": "Machine learning is a branch of AI that allows computers to learn patterns from data."
}
```

### How SFT Works

1. Prepare instruction-response examples.
2. Load a pretrained language model.
3. Tokenize the training examples.
4. Feed the examples into the model.
5. Calculate the training loss.
6. Update the trainable model parameters.
7. Evaluate the resulting model.

**Key point:** Instruction tuning is commonly implemented through SFT.

# 3. What Is PEFT?

PEFT stands for **Parameter-Efficient Fine-Tuning**.

It is a collection of techniques that adapt pretrained models while updating only a relatively small number of parameters.

### Why Do We Need PEFT?

Imagine a pretrained model has 7 billion parameters.

Updating all its parameters during fine-tuning can require significant GPU memory and computing resources.

PEFT provides methods to adapt the model without updating every original parameter.

### Full Fine-Tuning vs PEFT

| Full Fine-Tuning | PEFT |
|---|---|
| Updates most or all model parameters | Updates a small subset or additional parameters |
| Higher resource requirements | Often lower resource requirements |
| Can require substantial GPU memory | More practical on limited hardware |
| Stores a complete fine-tuned model | Can store smaller adapter weights |

PEFT does not make every fine-tuning task lightweight. Hardware requirements still depend on the model, training method, sequence length and batch size.

---

# 4. What Is LoRA?

LoRA stands for **Low-Rank Adaptation**.

It is one of the most popular PEFT techniques.

Instead of updating the original model weights directly, LoRA introduces smaller trainable matrices into selected model layers.

Typically:

- Original pretrained weights remain frozen.
- Additional LoRA parameters are trainable.
- Training focuses on those smaller additional parameters.

### Simple Example

Imagine a pretrained model has 7 billion parameters.

Instead of updating all 7 billion parameters, LoRA trains a much smaller set of additional parameters.

This can reduce training memory requirements and make fine-tuning more accessible.

### LoRA Workflow

```text
Pretrained Language Model
          |
          v
     Apply LoRA
          |
          v
 Freeze Original Weights
          |
          v
 Train LoRA Parameters
          |
          v
 Fine-Tuned Model
```

### Important Difference

- Instruction tuning describes WHAT we want the model to learn.
- SFT describes a supervised training approach.
- PEFT describes a family of parameter-efficient adaptation methods.
- LoRA is one specific PEFT technique.

These terms are related, but they do not mean the same thing.

# 6. Understanding Our Python Setup Code

We created a file called:

`setup_check.py`

Its purpose is to verify that the required libraries and PEFT components are installed correctly.

### Complete Code

```python
import torch
import transformers
import datasets
import peft
import accelerate
import trl

from peft import LoraConfig, get_peft_model

print("PEFT environment setup successful!")

print("Transformers:", transformers.__version__)
print("Datasets:", datasets.__version__)

print("Accelerate:", accelerate.__version__)
print("TRL:", trl.__version__)

print("CUDA available:", torch.cuda.is_available())

if torch.cuda.is_available():
    print("GPU:", torch.cuda.get_device_name(0))
else:
    print("Running on CPU")

print("LoRA tools imported successfully!")
```

### Step 1: Import Libraries

```python
import torch
import transformers
import datasets
import peft
import accelerate
import trl
```

The `import` statement makes installed Python libraries available to our program.

If a required library is missing, Python raises an import error.

### Step 2: Import LoRA Components

```python
from peft import LoraConfig, get_peft_model
```

**LoraConfig:** Defines the configuration for LoRA.

**get_peft_model:** Applies a PEFT configuration to a pretrained model.

We are checking that these components can be imported. We are not applying LoRA to a model yet.

### Step 3: Check Library Versions

```python
print("PyTorch:", torch.__version__)
print("PEFT:", peft.__version__)
```

The `__version__` attribute displays the installed library version.

This helps us identify compatibility problems and understand which software versions we are using.

### Step 4: Check GPU Availability

```python
print("CUDA available:", torch.cuda.is_available())
```

CUDA is a parallel computing platform used to run workloads on compatible NVIDIA GPUs.

This command checks whether PyTorch can access CUDA.

- `True`: CUDA is available to PyTorch.
- `False`: CUDA is not available to PyTorch.

A CPU-only environment can still be used to verify our setup.

### Step 5: Display GPU Information

```python
if torch.cuda.is_available():
    print("GPU:", torch.cuda.get_device_name(0))
else:
    print("Running on CPU")
```

This is an `if-else` conditional statement.

- If CUDA is available, display the first GPU's name.
- Otherwise, display that the program is running on CPU.
