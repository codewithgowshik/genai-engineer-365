## 1. What is Search Evaluation?

Search evaluation means checking whether a search engine produces useful and relevant results.

Getting results is not enough.

The important question is:

> Are the retrieved results relevant to the user's query?

For example:

```text
Query:
"What is a programming language?"

Expected relevant document:
doc1

doc1:
Python is a programming language.
```

If `doc1` appears in the retrieved results, the search successfully found a relevant document.

---

## 2. Relevance

**Relevance** means how useful a retrieved document is for the user's query.

Example:

```text
Query:
"I want to learn programming"

Result:
"Python is a programming language."
```

This is relevant.

But:

```text
Result:
"London is the capital of the United Kingdom."
```

is not relevant to that query.

Evaluation allows us to measure this instead of simply assuming the search engine works.

## 4. Hit Rate

For today's evaluation, we use a simple metric called **Hit Rate**.

Hit Rate tells us how many test queries successfully retrieved at least one expected relevant document.

Formula:

```text
Hit Rate = Successful Queries / Total Queries
```

Example:

```text
Successful queries = 3
Total queries = 4

Hit Rate = 3 / 4
Hit Rate = 75%
```

If all four queries successfully retrieve their expected document:

```text
Hit Rate = 4 / 4
Hit Rate = 100%
```

---

## 5. What Counts as a Successful Search?

Suppose:

```text
Query:
"What is a programming language?"

Expected:
doc1
```

The search returns:

```text
doc1
doc3
doc4
```

Because `doc1` is present:

```text
PASS
```

If the search returns:

```text
doc2
doc3
doc4
```

then:

```text
FAIL
```

because the expected relevant document was not retrieved.

---

## 6. Search Performance

Search quality is only one part of a search system.

We also care about **performance**.

Performance asks:

> How quickly does the search system return its results?

The time taken by a search operation is called **latency**.

The process is:

```text
Start Search
     ↓
Search runs
     ↓
Results returned
     ↓
End Search
```

Formula:

```text
Latency = End Time - Start Time
```

Lower latency generally means the system responds faster.

---

## 7. Measuring Latency in Python

Python provides `time.perf_counter()` for measuring elapsed time.

```python
import time

start = time.perf_counter()

results = search(
    query,
    k=3
)

end = time.perf_counter()

latency = end - start
```

The latency can then be displayed:

```python
print("Latency:", round(latency, 4), "seconds")
```

---

## 8. Average Latency

If we run multiple test queries, we can calculate the average latency.

Formula:

```text
Average Latency = Total Latency / Number of Queries
```

Example:

```text
Query 1 → 0.012 seconds
Query 2 → 0.010 seconds
Query 3 → 0.014 seconds
Query 4 → 0.012 seconds
```

Total:

```text
0.048 seconds
```

Average:

```text
0.048 / 4 = 0.012 seconds
```

So the average latency is:

```text
0.012 seconds
```

## 9. Evaluation Script

The evaluation script uses the existing search backend.

```python
import time

from src.search import search


test_set = [
    {
        "query": "What is a programming language?",
        "relevant_ids": ["doc1"]
    },
    {
        "query": "How do computers learn from data?",
        "relevant_ids": ["doc2"]
    },
    {
        "query": "What is a popular Italian food?",
        "relevant_ids": ["doc3"]
    },
    {
        "query": "What is the capital of the United Kingdom?",
        "relevant_ids": ["doc4"]
    }
]


successful = 0
total_latency = 0


for test in test_set:

    start = time.perf_counter()

    results = search(
        test["query"],
        k=3
    )

    end = time.perf_counter()

    latency = end - start
    total_latency += latency

    retrieved_ids = results["ids"][0]

    found = False

    for document_id in test["relevant_ids"]:
        if document_id in retrieved_ids:
            found = True

    if found:
        successful += 1
        status = "PASS"
    else:
        status = "FAIL"

    print(status)
    print("Query:", test["query"])
    print("Retrieved:", retrieved_ids)
    print("Latency:", round(latency, 4), "seconds")
    print()


hit_rate = successful / len(test_set)
average_latency = total_latency / len(test_set)


print("Evaluation complete")
print("Hit Rate:", round(hit_rate * 100, 2), "%")
print(
    "Average Latency:",
    round(average_latency, 4),
    "seconds"
)
```

## 11. Search Quality vs Search Performance

These are different measurements.

### Search Quality

Question:

> Did the search retrieve a relevant document?

Metric used today:

```text
Hit Rate
```

### Search Performance

Question:

> How quickly did the search return?

Metrics used today:

```text
Latency
Average Latency
```

Therefore:

```text
Search Quality
      ↓
    Hit Rate

Search Performance
      ↓
    Latency
```

A search engine ideally needs both:

```text
Relevant Results
        +
Fast Results
```
