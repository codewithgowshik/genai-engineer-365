## 1. Hardware Requirements for Local AI

Running an AI model locally requires memory and computing resources.

### RAM (Random Access Memory)

- Main memory used by your computer.
- Stores application data and model data.
- Larger models generally require more memory.

### VRAM (Video Random Access Memory)

- Memory available on your GPU.
- Stores model weights and other data during GPU inference.
- Limited VRAM can prevent a model from fitting entirely on the GPU.

### CPU (Central Processing Unit)

- Handles general computing operations.
- Can run AI inference.
- Usually slower than a suitable GPU for large language models.

### GPU (Graphics Processing Unit)

- Performs many calculations in parallel.
- Accelerates AI model inference.
- Has dedicated VRAM.

> **Important:** A model can sometimes run even when it doesn't fit entirely in VRAM. The runtime may use system RAM and CPU processing, but performance can decrease.

## 2. What Is Quantization?

Quantization is the process of reducing the numerical precision used to represent model weights.

For example:

- FP32 uses 32 bits per weight.
- FP16 uses 16 bits per weight.
- INT8 uses 8 bits per weight.
- 4-bit quantization uses approximately 4 bits per weight.

### Why Do We Need Quantization?

1. Reduce model file size.
2. Reduce memory consumption.
3. Run larger models on limited hardware.
4. Make local inference more accessible.

**Trade-off:** Lower numerical precision can sometimes reduce model output quality.

---

## 3. Model Memory Calculation

A simple formula for estimating model weight memory:

**Weight memory = Number of parameters × Bits per parameter ÷ 8**

Example: A 9-billion-parameter model.

| Precision | Bits | Approximate Weight Memory |
|-----------|-----:|--------------------------:|
| FP32      | 32   | 36 GB                     |
| FP16      | 16   | 18 GB                     |
| INT8      | 8    | 9 GB                      |
| 4-bit     | 4    | 4.5 GB                    |

These are theoretical estimates using decimal GB and account for weights only.

Actual memory requirements are higher because of:

- Model metadata.
- KV cache.
- Context length.
- Temporary computation buffers.
- Runtime overhead.

---

## 4. What Is GGUF?

GGUF is a model file format commonly used by local AI inference tools.

It stores model weights and metadata required by inference runtimes.

### Why Is GGUF Important?

- Supports different quantization formats.
- Helps distribute models for local inference.
- Is commonly used by llama.cpp-based tools.
- Is supported by Ollama for many models.

---

## 5. Common Quantization Levels

| Quantization | Description                        |
|--------------|------------------------------------|
| Q4           | Approximately 4-bit quantization   |
| Q5           | Approximately 5-bit quantization   |
| Q8           | Approximately 8-bit quantization   |

### General Comparison

**Q4**

- Lower memory requirements.
- Useful for hardware with limited memory.
- May have greater quality loss.

**Q5**

- Moderate memory requirements.
- Often provides a useful balance.

**Q8**

- Higher memory requirements.
- Generally preserves more numerical precision.

Actual performance and quality depend on the model, quantization method and hardware.

---

## 6. What Is Offloading?

Offloading means moving some model data or computation to another processor or memory location.

Example:

If your GPU has insufficient VRAM to hold the entire model, the inference runtime may use both GPU memory and system RAM.

This allows larger models to run on limited hardware.

However, transferring data between CPU and GPU memory can reduce inference speed.

## 8. Benchmarking a Quantized Model

When testing a quantized model, measure the following:

| Metric            | Purpose                                |
|-------------------|----------------------------------------|
| Model size        | Measures disk space required           |
| Quantization      | Identifies weight precision            |
| RAM usage         | Measures system memory consumption     |
| VRAM usage        | Measures GPU memory consumption        |
| Response time     | Measures generation duration           |
| Tokens per second | Measures generation speed              |
| Response quality  | Evaluates output accuracy and usefulness |

### Tokens Per Second

Ollama's API provides:

- `eval_count`: Number of generated tokens.
- `eval_duration`: Time spent generating tokens, in nanoseconds.

Formula:

```text
Tokens per second = eval_count ÷ (eval_duration ÷ 1,000,000,000)
```

Example:

If a model generates 100 tokens in 5 seconds:

```text
100 ÷ 5 = 20 tokens per second
```

For a fair comparison, use identical prompts and generation settings.
