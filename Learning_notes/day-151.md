## Part 1 — LEARN: Hosting (30 minutes)

### What is hosting?

Hosting makes an application available on a server so other people can access it over a network. Your current development setup runs locally:

| Component | Current setup |
|---|---|
| React + Vite frontend | `http://localhost:5173` |
| FastAPI backend | `http://localhost:8000` |
| FastAPI docs | `http://localhost:8000/docs` |
| ChromaDB | Local `chroma_data/` folder |
| LLM | External Gemini API |

`localhost` means the service is running on your computer. Other people cannot access it simply by opening your localhost address.

### What needs hosting in a RAG application?

1. **Frontend:** React + Vite user interface; can be deployed to static hosting.
2. **Backend:** FastAPI application; needs an application server or hosting service.
3. **Vector database:** Your ChromaDB persistence is currently local. A deployed backend needs durable storage or a separately hosted vector database.
4. **LLM API:** Gemini is external; keep its API key in the backend's secure environment variables.

Conceptual production architecture:

```text
User's Browser
      |
      v
Hosted React Frontend
      |
      | HTTPS API request
      v
Hosted FastAPI Backend
      |
      +------> Persistent Vector Store
      |
      +------> Gemini API
```

This is a possible deployment design, not a claim that your app is already deployed.

### Development vs production

| Development | Production |
|---|---|
| Localhost URLs | Public HTTPS domain |
| Local `.env` file | Hosting provider's secret settings |
| Local ChromaDB folder | Durable storage or hosted vector database |
| Debug/reload server | Production server configuration |
| Manual local testing | Monitoring, security and error handling |

### Hosting considerations for your RAG app

- Never commit your Gemini API key.
- Configure the frontend API base URL; it must not point to `localhost` after deployment.
- Configure FastAPI CORS for the deployed frontend's origin.
- Ensure ChromaDB data survives restarts and redeployments. Ephemeral storage may erase the index.
- Ensure documents are ingested in the deployment environment or the vector store is provisioned separately.
- Add logging, request limits and sensible error handling before making the API public.

You do not need to deploy today. Today's build task is to document the working interface.

## Part 2 — BUILD: Add screenshots or a GIF (30 minutes)

### Step 1 — Start the application

Open two Windows CMD terminals.

**Terminal 1 — Backend**, from the project root:

```cmd
cd /d "D:\python projects\gen 365\production-grade-rag"
.venv\Scripts\activate
uvicorn src.main:app --reload --port 8000
```

**Terminal 2 — Frontend:**

```cmd
cd /d "D:\python projects\gen 365\production-grade-rag\frontend"
npm run dev
```

Open the Vite URL, usually `http://localhost:5173`. Confirm that the UI loads and that you can submit a question successfully.

### Step 2 — Capture 2–3 screenshots

Recommended captures:

1. **Chat interface:** show the main application UI.
2. **Generated answer:** show a real question and the response.
3. **Source details:** only if your UI genuinely displays citations or source information.

Use `Win + Shift + S` to open Snipping Tool and capture the relevant area. Save as PNG. Keep the browser window tidy and text readable. Do not show API keys, personal details or unrelated browser tabs.

### Step 3 — Create the image folder

From the project root:

```cmd
mkdir docs
mkdir docs\images
```

Save your screenshots with clear names, for example:

```text
docs/
  images/
    rag-chat-interface.png
    rag-generated-answer.png
```

Only add a source-results screenshot if that feature exists in your current UI.

### Step 4 — Optional GIF

A short GIF can demonstrate the flow:

1. Show the empty chat screen.
2. Enter a question your document can answer.
3. Submit it.
4. Show the streamed response appearing.
5. End with the completed answer.

Aim for roughly 5–15 seconds. ScreenToGif is one option for recording and exporting a GIF. If this takes too long, use screenshots; a GIF is not required.

Save it as `docs/images/rag-demo.gif`.

### Step 5 — Embed media in `README.md`

Add a section to your root README:

```markdown

### Chat interface
![RAG chat interface](docs/images/rag-chat-interface.png)

### Generated answer

```

If you created a GIF:

```markdown

![RAG application demo](docs/images/rag-demo.gif)
```

These paths are relative to the repository root. Make sure the filenames match exactly.
