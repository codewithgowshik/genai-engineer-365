# 1. Introduction

Fine-tuning an AI model requires high-quality training data.

Yesterday, we created a small instruction dataset using JSONL.

Today, we are learning how to clean, validate and format that dataset before using it for model training.

Imagine we want to train an AI English tutor.

We prepare 1,000 examples containing English questions and answers.

However, our dataset contains:
- Incorrect answers.
- Duplicate examples.
- Empty instructions.
- Missing fields.
- Unnecessary spaces.
- Inconsistent formatting.

If we train a model using poor-quality data, it may learn incorrect or unwanted patterns.

This is why dataset preparation is an important part of the fine-tuning workflow.

**Key concept: Good training data is essential for good model performance.**

# 2. What Is Dataset Cleaning?

Dataset cleaning is the process of identifying and fixing problems in a dataset.

The objective is to improve data quality before training.

Common dataset-cleaning operations include:

| Operation | Explanation |
|---|---|
| Remove duplicates | Remove repeated examples |
| Remove empty records | Remove examples without required information |
| Trim whitespace | Remove unnecessary spaces |
| Validate data | Check whether records follow the required structure |
| Check data types | Ensure fields contain the expected data types |
| Standardise formatting | Make examples follow a consistent structure |
| Check content quality | Identify incorrect or irrelevant answers |

## 2.1 Removing Unnecessary Spaces

Before cleaning:

```json
{
  "instruction": "   Explain AI   ",
  "input": "",
  "output": " AI is artificial intelligence.   "
}
```

After cleaning:

```json
{
  "instruction": "Explain AI",
  "input": "",
  "output": "AI is artificial intelligence."
}
```

The `strip()` method in Python removes unnecessary whitespace from the beginning and end of a string.

## 2.2 Removing Empty Records

An empty record:

```json
{
  "instruction": "",
  "input": "",
  "output": ""
}
```

This example is not useful for supervised instruction fine-tuning.

We should remove it.

However, an empty input is perfectly acceptable when the instruction does not require additional information.

Example:

```json
{
  "instruction": "Explain artificial intelligence.",
  "input": "",
  "output": "Artificial intelligence allows computers to perform tasks that normally require human intelligence."
}
```

## 2.3 Removing Duplicate Records

Sometimes the same training example appears multiple times.

Example:

```jsonl
{"instruction":"Explain AI.","input":"","output":"AI allows computers to perform intelligent tasks."}
{"instruction":"Explain AI.","input":"","output":"AI allows computers to perform intelligent tasks."}
```

We can remove exact duplicates to avoid unnecessary repetition.

**Important:** Similar examples are not necessarily duplicates. Different examples can provide useful learning variety.

# 3. Understanding Fine-Tuning Dataset Formats

Different models and training frameworks expect different dataset structures.

There is no single universal format for every fine-tuning workflow.

Let's understand three common structures.

## 3.1 Alpaca Format

Alpaca is a popular instruction-following dataset format.

It uses three main fields:

- `instruction`
- `input`
- `output`

Example:

```json
{
  "instruction": "Explain machine learning.",
  "input": "",
  "output": "Machine learning allows computers to learn patterns from data."
}
```

### Field Explanation

| Field | Purpose |
|---|---|
| instruction | Defines what the model should do |
| input | Provides additional information |
| output | Contains the expected response |

### When is it useful?

- Instruction-following models.
- AI assistants.
- Text-generation tasks.
- Supervised fine-tuning.

---

## 3.2 ShareGPT Format

ShareGPT-style datasets represent conversations using a sequence of messages or conversation turns.

Example:

```json
{
  "conversations": [
    {
      "from": "human",
      "value": "What is artificial intelligence?"
    },
    {
      "from": "gpt",
      "value": "Artificial intelligence allows computers to perform tasks that normally require human intelligence."
    }
  ]
}
```

### How does it work?

Each conversation contains multiple messages.

- `human` represents the user's message.
- `gpt` represents the assistant's response.

This format is useful for conversational training.

---

## 3.3 Chat Messages Format

Many modern chat models and training frameworks use structured messages containing roles and content.

Example:

```json
{
  "messages": [
    {
      "role": "user",
      "content": "Explain artificial intelligence."
    },
    {
      "role": "assistant",
      "content": "Artificial intelligence allows computers to perform tasks that normally require human intelligence."
    }
  ]
}
```

Common roles:

| Role | Meaning |
|---|---|
| system | Defines the assistant's behaviour |
| user | Contains the user's message |
| assistant | Contains the assistant's response |

A conversation can contain multiple messages.

Example:

```json
{
  "messages": [
    {
      "role": "system",
      "content": "You are a helpful English teacher."
    },
    {
      "role": "user",
      "content": "What does professional communication mean?"
    },
    {
      "role": "assistant",
      "content": "Professional communication means sharing information clearly and respectfully in a workplace."
    }
  ]
}
```

# 4. Comparison of Dataset Formats

| Feature | Alpaca | ShareGPT | Chat Messages |
|---|---|---|---|
| Structure | Instruction, input, output | Conversation turns | Role, content |
| Main purpose | Instruction following | Conversational training | Chat-based training |
| Supports multiple turns naturally | Not by default | Yes | Yes |
| Common use | SFT datasets | Conversation datasets | Modern chat models |

**Important:** The training framework may require additional processing or conversion before these formats can be used.

The format must match the selected model and training pipeline.

# 5. What Is Data Validation?

Data validation means checking whether a dataset follows the rules we expect.

For our instruction dataset, every record should contain:

```text
instruction → String
input       → String
output      → String
```

### Valid Record

```json
{
  "instruction": "Explain AI.",
  "input": "",
  "output": "AI allows computers to perform tasks that normally require human intelligence."
}
```

### Invalid Record

```json
{
  "instruction": "Explain AI.",
  "input": "",
  "output": 12345
}
```

Why is this invalid?

Because the output should be a string, not a number.

### Difference Between Cleaning and Validation

| Dataset Cleaning | Data Validation |
|---|---|
| Improves data quality | Checks data correctness against rules |
| Removes duplicates | Checks required fields |
| Removes empty records | Checks data types |
| Removes unnecessary spaces | Checks JSON structure |
| Fixes formatting issues | Identifies invalid records |

**Remember:** Cleaning improves the dataset. Validation checks whether it follows the expected rules.

# 6. Understanding JSONL

JSONL stands for **JSON Lines**.

It is a text-based format where every line contains one independent JSON value.

### JSON Example

```json
[
  {
    "instruction": "Explain AI.",
    "input": "",
    "output": "AI allows computers to perform intelligent tasks."
  },
  {
    "instruction": "Explain machine learning.",
    "input": "",
    "output": "Machine learning allows computers to learn patterns from data."
  }
]
```

### JSONL Example

```jsonl
{"instruction":"Explain AI.","input":"","output":"AI allows computers to perform intelligent tasks."}
{"instruction":"Explain machine learning.","input":"","output":"Machine learning allows computers to learn patterns from data."}
```

### Main Differences

| JSON | JSONL |
|---|---|
| Can contain arrays and objects | Each line contains an independent JSON value |
| Array elements are separated by commas | No commas between separate records |
| Often used for configuration and API data | Useful for datasets and data processing |
| Usually `.json` | Usually `.jsonl` |

### Why Is JSONL Useful?

1. Easy to read and generate.
2. Each record can be processed independently.
3. Suitable for large datasets.
4. Easy to validate line by line.
5. Commonly supported by machine-learning data pipelines.

# 7. Dataset Preparation Workflow

Before fine-tuning a model, we should prepare the dataset properly.

```text
       Collect Raw Data
              |
              v
       Create Dataset
              |
              v
       Clean the Data
              |
              v
       Validate Records
              |
              v
       Check Data Quality
              |
              v
       Format for Model
              |
              v
       Split the Dataset
              |
              v
       Fine-Tuning
              |
              v
       Model Evaluation
```

### Step 1: Collect Raw Data

Gather examples from appropriate sources.

### Step 2: Create Dataset

Organise the information into a structured format.

### Step 3: Clean the Data

Remove duplicates, unnecessary spaces and unusable records.

### Step 4: Validate Records

Check JSON syntax, required fields and data types.

### Step 5: Check Data Quality

Review whether the instructions and answers are accurate, relevant and useful.

### Step 6: Format for the Model

Convert the dataset into the structure expected by the training framework.

### Step 7: Split the Dataset

Separate examples into training, validation and, where appropriate, test sets.

- Training set: Used to update model parameters.
- Validation set: Used to monitor training and make decisions.
- Test set: Used for final evaluation.

A common starting split might be:

| Dataset | Percentage |
|---|---:|
| Training | 80% |
| Validation | 10% |
| Testing | 10% |

The appropriate split depends on dataset size and project requirements.

For very small datasets, these percentages may not be practical.

### Step 8: Fine-Tuning

Train the selected pretrained model using the prepared training data.

### Step 9: Model Evaluation

Evaluate whether the fine-tuned model performs well on examples it did not train on.

# 8. Important Dataset Quality Principles

A good dataset should follow these principles.

## 8.1 Accuracy

Every expected answer should be factually correct.

## 8.2 Consistency

Use the same structure across all records.

## 8.3 Diversity

Include different types of instructions and examples.

## 8.4 Clarity

Instructions should be easy to understand.

## 8.5 Relevance

Examples should relate to the task we want the model to learn.

## 8.6 Avoid Duplicates

Remove unnecessary repeated examples.

## 8.7 Balanced Representation

Include suitable examples across the different tasks or categories you want the model to handle.

## 8.8 Avoid Data Leakage

Do not allow information from the test dataset to influence training.

For example, if the same example appears in both training and testing, evaluation results may be misleading.
