# Day 122 — Add Metadata Filters

## Objective

Today I learned how metadata can be attached to chunks in a RAG system and how metadata filters can restrict retrieval to a specific subset of stored information. This builds directly on parent-document retrieval from Day 121.

## What Is Metadata?

Metadata is additional structured information stored alongside a document or chunk. The actual text and embedding help the system understand and search the content, while metadata provides extra information about that content.

For example, a chunk can contain text such as:

```text
Machine learning allows computers to learn patterns from data.
```

Alongside the text, we can store metadata such as:

```text
source = documents.txt
topic = technology
parent_id = parent1
```

Metadata does not replace embeddings. It provides structured information that can be used to organize and filter the stored chunks.

## Why Metadata Filters Are Useful

As a RAG knowledge base becomes larger, searching every chunk may not always be desirable. Metadata allows the application to restrict retrieval to chunks that satisfy a particular condition.

For example, suppose the knowledge base contains information about technology, locations, and food. A query about machine learning could be restricted to chunks whose topic is `technology`.

The retrieval process becomes:

```text
User Question
      ↓
Metadata Filter
      ↓
Vector Similarity Search
      ↓
Relevant Chunks
      ↓
Context
      ↓
LLM
```

The metadata filter narrows the collection, while semantic search determines which remaining chunks are most similar to the query.

## Adding Metadata to Chroma

When chunks are stored in Chroma, metadata can be supplied together with the IDs, documents, and embeddings.

The structure used today was conceptually:

```python
collection.upsert(
    ids=ids,
    documents=texts,
    embeddings=embeddings.tolist(),
    metadatas=metadatas
)
```

Each chunk can therefore have its own metadata.

For today's experiment, the metadata included:

```text
source
 topic
parent_id
```

For example:

```text
chunk1
 ├── text
 ├── embedding
 └── metadata
       ├── source = documents.txt
       ├── topic = technology
       └── parent_id = parent1
```

## Metadata Filtering

Chroma supports filtering during retrieval using a `where` condition.

For example:

```python
results = collection.query(
    query_embeddings=[query_embedding.tolist()],
    n_results=3,
    where={
        "topic": "technology"
    }
)
```

This means that the retrieval operation is restricted to chunks whose metadata has `topic` equal to `technology`.

A retrieval function can make the filter optional:

```python
def retrieve(query, k=3, topic=None):

    query_embedding = model.encode(query)

    query_arguments = {
        "query_embeddings": [query_embedding.tolist()],
        "n_results": k,
        "include": [
            "documents",
            "distances",
            "metadatas"
        ]
    }

    if topic is not None:
        query_arguments["where"] = {
            "topic": topic
        }

    results = collection.query(**query_arguments)

    return results
```

When `topic` is not supplied, the system searches without that metadata restriction. When a topic is supplied, the `where` filter is added.

## Metadata and Embeddings Do Different Jobs

One of the most important concepts from today is that metadata and embeddings solve different problems.

Embeddings are used for semantic similarity. They help answer:

> Which stored content is most similar in meaning to the user's question?

Metadata filters are used for structured filtering. They help answer:

> Which stored content should be considered for this search?

The two can work together:

```text
                    RAG RETRIEVAL
                         │
             ┌───────────┴───────────┐
             ↓                       ↓
        Metadata Filter         Vector Search
             ↓                       ↓
      Which content?          Which is similar?
             └───────────┬───────────┘
                         ↓
                 Relevant Chunks
                         ↓
                        LLM
```

## Connection to Day 121

Day 121 introduced parent-document retrieval. Each child chunk could remember its `parent_id`, allowing the system to retrieve a larger parent context after finding a relevant small chunk.

Today's metadata system keeps that `parent_id` information while also adding fields such as `topic` and `source`.

The RAG retrieval flow is therefore becoming more structured:

```text
User Question
      ↓
Metadata Filter
      ↓
Retrieve Small Chunks
      ↓
Use Parent Information
      ↓
Build Context
      ↓
Generate Grounded Answer
      ↓
Source Citations
```
