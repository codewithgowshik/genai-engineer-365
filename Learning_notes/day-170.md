# 2. What Is Training Loss?

Training loss is a numerical measurement of how different a model's predictions are from the expected target outputs during training.

In simple terms, it measures how poorly or accurately the model is predicting the expected answers according to its training objective.

For example:

**Instruction:**

What is Python?

**Expected output:**

Python is a programming language.

The model generates a prediction. During training, a loss function compares its predictions with the expected output.

The resulting loss value helps the training process calculate how to update the trainable model parameters.

### Important points

- High loss generally indicates that predictions are poor according to the training objective.
- Lower loss generally indicates better fitting to the training examples.
- Training loss changing over time helps us monitor learning.
- Low training loss does not guarantee good performance on unseen data.

# 3. What Is a Loss Curve?

A loss curve is a graph that displays how training loss changes during the training process.

It normally contains:

- X-axis: Training steps or epochs.
- Y-axis: Loss value.

Example:

| Training Step | Training Loss |
|---:|---:|
| 10 | 2.50 |
| 20 | 2.10 |
| 30 | 1.80 |
| 40 | 1.45 |
| 50 | 1.20 |
| 60 | 0.95 |

In this example, training loss decreases as training progresses.

This suggests that the model is fitting the training data better.

**A loss curve helps us understand how training behaves over time rather than looking at one loss value.**

# 4. Understanding Different Loss Curves

## 4.1 Healthy Training

A healthy training curve often shows a gradual decrease in training loss.

Example:


Interpretation:

- Training loss is decreasing.
- Training appears to be progressing.

However, we still need validation results to determine whether the model generalises well.

## 4.2 Training Loss Is Not Decreasing

Example:

```text
Loss
 |
 |------------
 |
 |
 +---------------- Training Steps
```

Possible reasons:

- Learning rate is too low.
- Dataset quality is poor.
- Model configuration is incorrect.
- Training is not updating the intended parameters.
- The learning rate or optimiser settings need investigation.

## 4.3 Unstable Training

Example:

```text
Loss
 |
 | /\    /\
 |/  \__/  \__
 |
 +---------------- Training Steps
```

Possible reasons:

- Learning rate is too high.
- Gradients are unstable.
- Dataset examples vary significantly.
- Training configuration needs adjustment.

Small fluctuations are normal. Large and persistent spikes require investigation.

# 5. What Is Overfitting?

Overfitting occurs when a model learns the training examples too closely but performs poorly on new, unseen examples.

Example:

| Epoch | Training Loss | Validation Loss |
|---:|---:|---:|
| 1 | 2.50 | 2.70 |
| 2 | 1.80 | 2.00 |
| 3 | 1.20 | 1.90 |
| 4 | 0.70 | 2.30 |
| 5 | 0.30 | 2.90 |

Observe the results:

- Training loss continuously decreases.
- Validation loss initially decreases.
- Validation loss starts increasing after Epoch 3.

This can indicate overfitting.

The model is improving on its training data but becoming worse on unseen validation data.

### How to reduce overfitting

1. Use a representative training dataset.
2. Remove duplicate examples.
3. Improve dataset quality.
4. Monitor validation loss.
5. Reduce the number of training epochs if appropriate.
6. Adjust learning rate and regularisation.
7. Use early stopping when suitable.

# 6. Training Loss vs Validation Loss

These two measurements are important when evaluating a fine-tuning experiment.

| Training Loss | Validation Loss |
|---|---|
| Measured using training data | Measured using validation data |
| Used to optimise model parameters | Used to monitor generalisation |
| Shows how well the model fits training examples | Shows performance on separate examples |
| Usually decreases during successful training | May decrease, stabilise or increase |

### Why do we need both?

Imagine:

- Training loss = 0.3
- Validation loss = 2.9

The model has fitted its training examples well, but its performance on unseen validation examples may be poor.

This is why monitoring training loss alone is insufficient.

**Important:** Validation loss is not automatically calculated just because training loss is logged. We must configure an evaluation dataset and evaluation process.

# 7. What Is a Training Step?

A training step is an optimiser update.

During training:

1. The model processes a batch of examples.
2. It generates predictions.
3. The loss function calculates the error.
4. Backpropagation calculates gradients.
5. The optimiser updates trainable parameters.

One training step normally corresponds to one optimiser update.

### Relationship with gradient accumulation

Suppose:

```text
Per-device batch size = 1
Gradient accumulation = 4
Number of GPUs = 1
```

Effective batch size:

```text
1 × 4 × 1 = 4
```

The model processes four microbatches before an optimiser update, assuming a complete accumulation cycle.

Therefore, training steps and individual forward passes are not necessarily the same thing.

# 11. Extracting Actual Training Loss

After running the Day 169 training process, we can extract the actual recorded training loss.

Example:

```python
logs = trainer.state.log_history

for entry in logs:
    if "loss" in entry:
        print(
            "Step:", entry.get("step"),
            "| Loss:", entry["loss"]
        )
```

This code:

1. Retrieves training history.
2. Iterates through recorded log entries.
3. Checks whether a loss value exists.
4. Prints the training step and loss.

## Plot Actual Training Loss

```python
actual_steps = []
actual_losses = []

for entry in trainer.state.log_history:

    if "loss" in entry:

        actual_steps.append(entry["step"])
        actual_losses.append(entry["loss"])


if actual_losses:

    plt.figure(figsize=(10, 5))

    plt.plot(
        actual_steps,
        actual_losses,
        marker="o",
        label="Actual Training Loss"
    )

    plt.xlabel("Training Steps")
    plt.ylabel("Training Loss")

    plt.title("Day 170 - Actual LoRA Training Loss")

    plt.legend()
    plt.grid(True)

    plt.savefig("actual_training_loss.png", dpi=300)

    plt.show()

else:

    print("No training loss recorded yet.")
```

**Important:** This code must run after training has started and generated loss logs. If training has not run, there will be no actual training loss to plot.
