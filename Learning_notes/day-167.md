# 2. What Is QLoRA?

QLoRA stands for **Quantized Low-Rank Adaptation**.

It is a parameter-efficient fine-tuning technique that combines:

- Quantization
- LoRA (Low-Rank Adaptation)

QLoRA makes it possible to fine-tune large language models using significantly less GPU memory.

### Why Do We Need QLoRA?

Large language models contain billions of parameters.

For example:
- A 7-billion-parameter model.
- A 13-billion-parameter model.
- A 70-billion-parameter model.

Loading and fine-tuning these models can require substantial GPU memory.

Traditional fine-tuning may require storing:
- Model weights.
- Gradients.
- Optimizer states.
- Intermediate activations.

This can make fine-tuning expensive or impossible on consumer hardware.

QLoRA addresses this memory problem.

# 3. Understanding Quantization

Quantization is the process of representing model weights using fewer bits.

For example:

| Data Type | Bits per Parameter |
|---|---:|
| FP32 | 32 bits |
| FP16 | 16 bits |
| BF16 | 16 bits |
| INT8 | 8 bits |
| NF4 | 4 bits |

A model stored using 32-bit floating-point values requires considerably more memory than the same model stored using 4-bit values.

### Example

Imagine a model containing 7 billion parameters.

Approximate weight storage:

- FP32: 28 GB
- FP16: 14 GB
- 8-bit: 7 GB
- 4-bit: 3.5 GB

These are theoretical estimates for weight storage alone. Actual GPU memory requirements are higher because training also needs memory for activations, adapters and other operations.

### What Is NF4?

NF4 means NormalFloat 4-bit.

It is a 4-bit data type designed for quantizing normally distributed model weights.

QLoRA commonly uses NF4 to reduce memory consumption.

---

# 4. How QLoRA Works

QLoRA combines quantization with LoRA.

The process:

1. Load the pretrained model.
2. Quantize the model weights to 4-bit.
3. Freeze the original quantized model weights.
4. Add trainable LoRA adapters.
5. Train only the LoRA adapter parameters.
6. Save the trained adapters.

The original model remains frozen while the smaller LoRA adapters learn the new task.

### QLoRA Architecture

```text
Pretrained Language Model
          |
          v
   4-bit Quantization
          |
          v
  Frozen Model Weights
          |
          v
   Add LoRA Adapters
          |
          v
  Train Adapter Parameters
          |
          v
   Save Trained Adapters
```

### Important Components

| Component | Purpose |
|---|---|
| Quantization | Reduces memory requirements |
| NF4 | Efficient 4-bit representation |
| LoRA | Adds small trainable matrices |
| Frozen weights | Prevents updating original model weights |
| Adapters | Learn task-specific information |
| Backpropagation | Updates trainable adapter parameters |

QLoRA also uses techniques such as double quantization and paged optimizers to improve memory efficiency.

---

# 5. LoRA vs QLoRA

| Feature | LoRA | QLoRA |
|---|---|---|
| Full model weights | Usually higher precision | Quantized, commonly 4-bit |
| Original weights | Frozen | Frozen |
| Trainable parameters | LoRA adapters | LoRA adapters |
| Memory requirements | Lower than full fine-tuning | Generally lower than LoRA |
| Main purpose | Parameter-efficient fine-tuning | Memory-efficient parameter-efficient fine-tuning |

### Key Difference

LoRA reduces the number of trainable parameters.

QLoRA additionally reduces the memory needed to store the frozen base model.

**Remember: QLoRA does not mean training every model parameter in 4-bit. The base model is quantized, while the LoRA adapters are trained.**

# 6. What Is Model Evaluation?

Model evaluation is the process of measuring how well a machine learning model performs on a particular task.

Training a model does not automatically mean that it performs well.

We need to test whether the model produces useful, accurate and consistent responses.

### Why Is Evaluation Important?

Evaluation helps us understand:

- Whether the model learned the task.
- Whether its answers are accurate.
- Whether it follows instructions.
- Whether it generates irrelevant responses.
- Whether fine-tuning improved performance.
- Whether the model is suitable for real-world use.

Without evaluation, we cannot reliably determine whether fine-tuning was successful.

---

# 7. Training Data vs Validation Data vs Test Data

A dataset is commonly divided into three parts.

| Dataset | Purpose |
|---|---|
| Training set | Used to train the model |
| Validation set | Used to monitor performance and tune settings |
| Test set | Used for final evaluation |

### Example: 1000 Records

A possible split:

- Training: 800 records (80%)
- Validation: 100 records (10%)
- Testing: 100 records (10%)

These percentages are examples, not mandatory rules.

### What Is Data Leakage?

Data leakage happens when information from the test dataset influences the training process.

For example:

If the same question and answer appear in both training and testing datasets, the model may simply memorise the answer.

This creates misleading evaluation results.

**Rule: Keep the test dataset separate from training and model-selection decisions.**

# 8. Important Evaluation Metrics

Different tasks require different evaluation metrics.

### 1. Accuracy

Measures the percentage of correct predictions.

Example:

If a model answers 90 out of 100 questions correctly:

Accuracy = 90%

Best suited to tasks with clearly defined correct answers.

### 2. Exact Match (EM)

Measures whether the generated answer exactly matches the expected answer.

Example:

Expected: Paris

Generated: Paris

Result: Match.

However:

Expected: Paris

Generated: The capital is Paris.

Result: No exact match.

### 3. Precision

Measures how many of the model's positive predictions were actually correct.

### 4. Recall

Measures how many of the actual positive cases the model successfully identified.

### 5. F1 Score

Combines precision and recall into a single metric.

F1 Score = 2 × (Precision × Recall) / (Precision + Recall)

Useful when evaluating classification tasks, especially when classes are imbalanced.

### 6. ROUGE

Measures the overlap of words or sequences between generated text and reference text.

Commonly used in summarisation evaluation.

### 7. BLEU

Measures n-gram overlap between generated text and reference text.

Commonly used in machine translation.

### 8. Human Evaluation

Humans review model responses based on criteria such as:

- Accuracy.
- Relevance.
- Clarity.
- Instruction following.
- Completeness.

Human evaluation is particularly useful when multiple answers can be correct.

**Important:** No single metric is suitable for every language-model task.

# 9. Define an Evaluation for Our Fine-Tuning Task

For our instruction-following model, we need to evaluate whether the model follows instructions and generates useful responses.

We should compare:

1. The original pretrained model.
2. The fine-tuned model.

Both models should receive the same evaluation questions.

### Evaluation Dataset

Create a separate test dataset containing questions that were not used during training.

Example:

```json
{"instruction": "Explain machine learning in simple terms.", "input": "", "expected_output": "Machine learning is a type of AI that allows computers to learn patterns from data."}
{"instruction": "What is Python?", "input": "", "expected_output": "Python is a popular programming language used for software development, automation, and data science."}
{"instruction": "Explain what an API does.", "input": "", "expected_output": "An API allows different software applications to communicate with each other."}
```

These are illustrative evaluation examples.

### Evaluation Criteria

| Criterion | What We Measure |
|---|---|
| Instruction Following | Does the model follow the requested instruction? |
| Accuracy | Is the information factually correct? |
| Relevance | Does the response answer the actual question? |
| Clarity | Is the response understandable? |
| Completeness | Does the response cover the important points? |

### Scoring System

Use a simple 1–5 rating.

| Score | Meaning |
|---|---|
| 1 | Very poor |
| 2 | Poor |
| 3 | Acceptable |
| 4 | Good |
| 5 | Excellent |

For each response, evaluate all five criteria.

Calculate the average score:

Average Score = Total Score / Number of Ratings

For example:

If a response receives:

- Instruction Following: 5
- Accuracy: 4
- Relevance: 5
- Clarity: 4
- Completeness: 4

Total = 22

Average = 22 / 5 = 4.4 / 5

# 11. Baseline vs Fine-Tuned Model

A baseline is the original model before fine-tuning.

We compare its performance with the fine-tuned model.

Example results table:

| Evaluation Metric | Base Model | Fine-Tuned Model |
|---|---:|---:|
| Instruction Following | 3.2 | 4.5 |
| Accuracy | 3.5 | 4.2 |
| Relevance | 3.8 | 4.6 |
| Clarity | 4.0 | 4.4 |
| Completeness | 3.4 | 4.3 |

These are hypothetical scores, not actual experimental results.

If the fine-tuned model performs better on the evaluation dataset, it provides evidence that fine-tuning improved performance on the measured task.

However, we must also check for regressions and ensure the evaluation dataset represents real-world usage.
