# Day 144 · Build a Streaming Chat UI

**Phase:** Phase 4 — Retrieval-Augmented Generation (RAG)  
**Week:** Week 21 — Build Project 4 (Production RAG App)

## Goal

Build a simple chat interface that displays a user's question and streams an assistant response gradually, instead of waiting for the entire answer to finish.

## LEARN — A Chat UI for RAG

A RAG chat interface usually needs:

- A message area showing user and assistant messages.
- A text box for entering a question.
- A send button.
- A loading or streaming state while the answer arrives.
- Clear error handling if the request fails.
- A place to show source citations when the backend returns them.

**Streaming** means the UI receives and displays pieces of a response as they arrive. It improves perceived responsiveness, but it does not make the answer more accurate by itself.

A typical flow is:

1. The user submits a question.
2. The UI sends the question to the backend.
3. The backend retrieves relevant passages and generates an answer.
4. The backend sends response chunks as they become available.
5. The UI appends each chunk to the assistant's message.
6. The completed message is shown in the conversation.

For this day's prototype, focus on the chat interface and streaming behaviour. If the backend does not yet expose a streaming endpoint, use a small mock stream in the UI or implement the UI against a clearly defined endpoint contract. Do not imply that simulated streaming is real LLM token streaming.

## BUILD — Streaming Chat UI

### 1. Choose the UI location

Build the interface in the frontend location that already exists in your repository. If `production-rag-app` currently contains only the Python backend, add a separate frontend folder rather than placing React code inside `src/`.

Suggested structure if no frontend exists:

```text
production-rag-app/
├── frontend/
│   ├── index.html
│   ├── package.json
│   └── src/
│       ├── App.jsx
│       ├── App.css
│       └── main.jsx
└── src/
    ├── ingestion.py
    ├── retrieval.py
    └── reranking.py
```

### 2. Build the chat layout

Include:

- A header titled **Production RAG Assistant**.
- A scrollable conversation area.
- User messages aligned to the right.
- Assistant messages aligned to the left.
- A multiline input field.
- A Send button.
- A small status label such as **Thinking…** or **Streaming…**.
- A source area for citations when available.

Keep the design responsive and accessible. The Send button should be disabled while a response is streaming, and Enter should send the message while Shift+Enter inserts a new line.

### 3. Implement streaming behaviour

Use the browser's Fetch API with a `ReadableStream` reader if the backend will return a streaming HTTP response. Read incoming chunks and append their decoded text to the current assistant message.

The frontend needs a matching backend contract. For example, the backend could return `text/plain` chunks, or Server-Sent Events (`text/event-stream`) with a documented event format. Choose one format and use it consistently.

If the backend streaming endpoint is not implemented yet, use a mock stream for the UI prototype and label it as simulated. Connect it to real LLM streaming in a later integration step.

### 4. Handle edge cases

- Ignore empty or whitespace-only messages.
- Show an error message if the request fails.
- Restore the input and Send button after completion or failure.
- Avoid submitting the same message repeatedly while a response is active.
- Keep earlier conversation messages visible.
- Scroll to the newest message as content arrives.
- Do not display citation links unless the backend provides valid source information.

### 5. Test the UI

- Send a short question.
- Confirm the user message appears immediately.
- Confirm the assistant response appears incrementally.
- Send a second question after the first response finishes.
- Try an empty message.
- Simulate a request failure and confirm the UI recovers.
- Resize the browser to check the layout on a narrow screen.

## Git — Commit and Push

After testing, run these commands from the repository root:

```powershell
git status
git add frontend README.md
git commit -m "Day 144: build streaming chat UI"
git push
```

If your frontend is in a different folder, substitute its actual path. Only add files you created or changed.

## Key Takeaways

- A chat UI needs message state, input handling, loading state, and error handling.
- Streaming displays response chunks as they arrive instead of waiting for the full response.
- A frontend can only stream real model output when the backend exposes a compatible streaming endpoint.
- Keep citations tied to source metadata returned by the backend.
