## Grounding

Grounding means making the generated answer depend on the information retrieved from the knowledge base instead of allowing the language model to freely generate an unsupported answer.

In a RAG system, retrieval provides the information that the model should use when answering the user's question. The retrieved context therefore acts as the evidence for the generated answer.

The basic idea is:

```text
User Question
      ↓
Retrieve Relevant Information
      ↓
Retrieved Context
      ↓
LLM
      ↓
Grounded Answer
```

A grounded answer should be supported by the retrieved context. If the required information is not present, the system should follow the prompt instruction and say that the information is not available rather than inventing an answer.

## Citations

Citations connect the generated answer back to the information retrieved by the system.

A RAG response can therefore contain two important parts:

```text
Answer
  ↓
Source Citations
```

The citations allow us to inspect which retrieved chunks were used as the source information for the response.

This is especially useful when testing the system because we can check whether the answer and its sources actually correspond to the user's question.

## Complete RAG Pipeline

After today's testing, the complete conceptual pipeline is:

```text
User Question
      ↓
Query Embedding
      ↓
Retrieve Relevant Chunks
      ↓
Context
      ↓
Prompt Template
      ↓
LLM
      ↓
Grounded Answer
      ↓
Source Citations
```

Each stage has a different responsibility. Retrieval finds relevant information, the prompt template provides that information to the LLM, the LLM generates the response, and the citations show the sources associated with the retrieved information.

## What I Need to Check

For every test question, I should check three things.

### 1. Retrieval

Did the system retrieve information that is relevant to the question?

If the retrieved chunks are unrelated, the generation stage cannot reliably produce a grounded answer.

### 2. Answer

Is the generated answer actually supported by the retrieved context?

A good answer should not introduce information that is unrelated to or unsupported by the retrieved context.

### 3. Citation

Does the displayed citation correspond to the information retrieved for the question?

The source should provide evidence that is relevant to the generated answer.

## Testing Unsupported Questions

A good RAG evaluation should also include questions that the knowledge base cannot answer.

For example:

```text
How do I repair a car engine?
```

If the dataset does not contain information about repairing car engines, the system should not confidently invent an answer.

Instead, the RAG prompt should guide the model to respond that the information is not available when the required information cannot be found in the retrieved context.

This test is important because RAG is not only about producing answers. It is also about controlling what information the answer is based on.

## What Can Fail?

Testing the complete pipeline helps identify different types of problems.

The retriever can return irrelevant chunks. In that situation, the problem is mainly in retrieval.

The retriever can find relevant information but the LLM can produce an answer that is not supported by the context. In that situation, the generation or prompting stage needs investigation.

The answer can be grounded but the citation can point to the wrong source. In that situation, the source-tracking part of the pipeline needs improvement.

This makes real-question testing useful because it helps identify which part of the RAG pipeline needs attention.
