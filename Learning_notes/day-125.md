# Day 125 — Hybrid Search for RAG

## Objective

Today I learned about **hybrid search** and added it to my RAG retrieval workflow.

The main idea is to combine **keyword search** and **semantic search** so that the retrieval system can use both exact word matching and meaning-based matching.

---

## What Is Hybrid Search?

Hybrid search combines two different retrieval methods:

```text
Keyword Search
      +
Semantic Search
      ↓
Hybrid Search
```

Keyword search looks for exact words or phrases in documents.

Semantic search looks for documents that have a similar meaning to the user's query, even when the exact words are different.

Hybrid search combines the strengths of both approaches.

---

## Keyword Search

Keyword search focuses on the actual words in the query.

For example:

```text
Query:
Python programming
```

A document containing:

```text
Python is a programming language used to build software.
```

would receive a strong keyword match because it contains the words `Python` and `programming`.

Keyword search is especially useful when the exact term matters, such as a technical name, product name, or specific phrase.

---

## Semantic Search

Semantic search focuses on meaning rather than only exact words.

For example:

```text
Query:
How can I create software?
```

A document such as:

```text
Python is a programming language used to build software.
```

can be considered relevant even if the wording is not exactly the same.

In my project, semantic search uses embeddings and Chroma to find similar documents.

---

## Why Use Both?

Keyword and semantic search have different strengths.

| Search Method | Main Strength |
|---|---|
| Keyword search | Exact words and phrases |
| Semantic search | Meaning and concepts |
| Hybrid search | Combines both |

Semantic search can understand the meaning of a query, while keyword search can make sure important exact terms are not missed.

Combining them can therefore improve retrieval quality.

---

## Hybrid Score

A simple way to combine the two methods is to calculate a weighted score.

For example:

```text
Hybrid Score =
(Keyword Score × 0.3) +
(Semantic Score × 0.7)
```

If a document has:

```text
Keyword Score  = 0.8
Semantic Score = 0.7
```

then:

```text
(0.8 × 0.3) + (0.7 × 0.7)

= 0.24 + 0.49

= 0.73
```

The final hybrid score can then be used to rank the retrieved documents.

The weights are configurable. Different datasets may require different balances between keyword and semantic retrieval.

## How It Fits Into My RAG Project

Before hybrid search, my retrieval workflow was mainly based on semantic search.

After adding hybrid search, the retrieval layer becomes:

```text
User Question
      ↓
Multi-Query Retrieval
      ↓
 ┌───────────────┐
 │               │
 ↓               ↓
Keyword       Semantic
Search        Search
 │               │
 └───────┬───────┘
         ↓
   Hybrid Ranking
         ↓
Relevant Documents
         ↓
RAG Context
         ↓
LLM Answer
```

This means hybrid search improves the retrieval stage before the retrieved information is passed into the RAG generation process.
