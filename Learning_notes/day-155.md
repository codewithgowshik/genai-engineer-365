## 1. LEARN — Open-weight models vs closed models

### Open-weight models

An open-weight model makes its trained model weights available for people to download and run, subject to the model's licence and terms.

Depending on the model and licence, developers may be able to run the model on their own computer or server, integrate it into applications, configure inference settings, and adapt or fine-tune it where permitted.

**Important:** “Open-weight” does not automatically mean fully open-source. Training data, training code and other parts of model development may not be public.

### Closed models

A closed model generally does not make its model weights publicly available. Developers commonly access it through a provider-managed service or API. The provider manages the inference infrastructure, while the developer sends requests and receives responses.

### Comparison

| Open-weight model | Closed model |
|---|---|
| Weights are available under a licence | Weights are generally not publicly available |
| Can often be run locally | Commonly accessed through a hosted API |
| Developer manages local/server hardware when self-hosting | Provider manages inference infrastructure |
| May offer more deployment control | Convenient access without managing model hosting |
| Licence conditions still apply | Provider's service terms and API policies apply |

Examples discussed today:
- Qwen models: open-weight model family.
- GPT and Claude: examples of closed, provider-hosted model families.

## 3. How local inference works

The basic workflow is:

```text
             USER PROMPT
                  |
                  v
             OLLAMA RUNTIME
                  |
                  v
            LOAD MODEL WEIGHTS
                  |
                  v
              TOKENIZATION
                  |
                  v
             MODEL INFERENCE
                  |
                  v
            TOKEN GENERATION
                  |
                  v
             FINAL RESPONSE
```

### Key concepts

**Inference:** Running a trained model to generate a prediction or response from an input.

**Local inference:** Running model inference on hardware that you control, such as your own computer.

**Ollama runtime:** Software that helps download, manage and run supported models locally.

**Tokenization:** Converting input text into tokens that the model can process.

**Quantization:** Representing model weights with lower numerical precision to reduce storage and memory requirements, often with trade-offs in quality and performance.

**Context window:** The amount of input and conversation context a model can process for a request. The available context depends on the model and its configuration.

---

## 4. Local inference vs cloud inference

| Local inference | Cloud inference |
|---|---|
| Model runs on your computer or your own server | Model runs on provider-managed infrastructure |
| Can work offline after downloading the model, depending on setup | Usually requires an internet connection |
| Uses your available CPU, GPU and RAM | Uses the provider's compute infrastructure |
| You manage model storage and runtime | Provider manages model hosting |
| No per-request cloud model API call is required | API pricing or service limits may apply |

Local inference does not mean running a model is completely cost-free: your computer uses electricity and its hardware has performance and memory limits.
