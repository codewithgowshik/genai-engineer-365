# Day 123 — Add LLM Query Rewriting

## Objective

Today I learned how query rewriting and query expansion can improve retrieval in a Retrieval-Augmented Generation (RAG) system. I then added the idea of using an LLM to rewrite a user's question before sending it to the retrieval system.

The main goal is to make the search query clearer and more useful for semantic retrieval without changing the original meaning of the user's question.

## What Is Query Rewriting?

Query rewriting means transforming the user's original question into a clearer query that is better suited for a retrieval system.

For example:

```text
Original query:
How do computers learn?

Rewritten query:
How does machine learning allow computers to learn patterns from data and make predictions?
```

The rewritten query is more specific and contains concepts that can help the retrieval system find relevant information.

The important point is that the rewriting step does not answer the user's question. Its job is to create a better search query.

## What Is Query Expansion?

Query expansion is related to query rewriting, but instead of only changing the wording, it can add related terms or concepts to the query.

For example:

```text
Original:
computer learning

Expanded:
computer learning machine learning patterns data predictions
```

Both rewriting and expansion are intended to improve retrieval quality.

## Why Query Rewriting Is Useful

Users often ask questions using short, vague, or conversational language. The wording used by the user may not closely match the wording stored in the knowledge base.

For example, a user might ask:

```text
How can a computer get better from experience?
```

The knowledge base might contain:

```text
Machine learning allows computers to learn patterns from data and make predictions.
```

An LLM can rewrite the question into something closer to the concepts in the knowledge base:

```text
How does machine learning enable computers to learn patterns from data and improve predictions?
```

This rewritten query can then be embedded and used for semantic retrieval.

## Where Query Rewriting Fits in RAG

Before query rewriting, the retrieval flow was approximately:

After adding query rewriting:

The new step happens before retrieval.

## Two Different LLM Jobs

After adding query rewriting, the RAG system can use an LLM for two different purposes.

### 1. Query Rewriting

The first LLM improves the search query.

```text
User:
What is AI?

↓

Rewritten query:
What is artificial intelligence and what tasks can AI systems perform?
```

Its job is to improve retrieval.

### 2. Answer Generation

The second LLM receives the user's question together with retrieved context and generates the final answer.

```text
Question + Retrieved Context
            ↓
           LLM
            ↓
         Answer
```

Its job is to generate the answer using the retrieved information.

These two jobs should not be confused.

## Query Rewriting Prompt

A simple prompt for the query rewriting LLM is:

```text
Rewrite the following user question into a clear search query
for a knowledge retrieval system.

Keep the original meaning.
Do not answer the question.

User question:
{query}

Return only the rewritten query.
```

The instruction to not answer the question is important because this LLM step is only responsible for producing a retrieval query.

## Original Query vs Rewritten Query

The system should keep both the original query and the rewritten query.

For example:

```text
Original query:
How do computers learn?

Rewritten query:
How does machine learning allow computers to learn patterns from data?
```

The original query remains useful for the user interface, final answer generation, logging, debugging, and evaluation.

The rewritten query is mainly used for retrieval.

Therefore:

```text
Original query → user-facing
Rewritten query → retrieval-facing
```

## What I Learned Today

- Query rewriting transforms a user's question into a clearer retrieval query.
- Query expansion can add related terms and concepts to a search query.
- Query rewriting happens before retrieval in a RAG pipeline.
- An LLM can be used to improve a query before it is converted into an embedding.
- Query rewriting should preserve the user's original meaning.
- The query rewriting LLM should rewrite the query rather than answer it.
- The original query and rewritten query should be kept separately.
- Query rewriting can help when the user's wording does not closely match the wording in the knowledge base.

## Important Limitation

Query rewriting does not create new knowledge.

If the knowledge base does not contain information about a topic, rewriting the question cannot make that information appear in the database.

The purpose of rewriting is to improve the query used for retrieval, not to replace the knowledge base or generate the final answer.
