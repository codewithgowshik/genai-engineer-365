# 2. What Is a LoRA Adapter?

LoRA stands for **Low-Rank Adaptation**.

It is a Parameter-Efficient Fine-Tuning (PEFT) technique used to adapt pretrained models without updating all their original parameters.

Instead of training every parameter in the model, LoRA introduces smaller trainable matrices into selected model layers.

During training:

- Original model weights are generally frozen.
- LoRA adapter parameters are trained.
- The adapter learns task-specific adjustments.
- The trained adapter can be saved separately.

For example:

**Base Model:**

`Qwen/Qwen2.5-0.5B`

**Fine-Tuned Model:**

`Qwen/Qwen2.5-0.5B + Trained LoRA Adapter`

# 3. Why Should We Save LoRA Adapters?

Imagine spending one hour training a model in Google Colab.

After training, your Colab runtime disconnects.

If you have not saved your adapter, you may lose your training results.

Saving the adapter allows us to:

1. Reuse the trained model later.
2. Avoid repeating the training process.
3. Share the adapter with other developers.
4. Compare different fine-tuned versions.
5. Deploy the adapter with its original base model.
6. Keep a record of our experiments.

**Important:** Saving an adapter does not mean saving the entire original model.

It saves the trained adapter parameters and their configuration.

# 4. What Does a Saved LoRA Adapter Contain?

A typical PEFT adapter directory contains:

```text
day173-lora-adapter/
│
├── adapter_config.json
├── adapter_model.safetensors
└── README.md
```

### adapter_config.json

Contains the adapter configuration.

It records information such as:

- LoRA rank.
- LoRA alpha.
- LoRA dropout.
- Target modules.
- Base model reference.
- PEFT task type.

Example:

```json
{
  "r": 8,
  "lora_alpha": 16,
  "lora_dropout": 0.05,
  "bias": "none",
  "task_type": "CAUSAL_LM"
}
```

This is an illustrative configuration. Your actual file may contain additional fields.

### adapter_model.safetensors

Contains the trained adapter weights.

These are the learned parameters produced during fine-tuning.

The `.safetensors` format stores tensors in a format designed for safe and efficient loading.

### README.md

Documents the adapter.

It can include:

- Model name.
- Training dataset information.
- Training configuration.
- Training date.
- Evaluation results.
- Instructions for loading the adapter.

# 5. Saving a LoRA Adapter Using PEFT

The PEFT library provides a method called:

`save_pretrained()`

This method saves a trained PEFT model to a directory.

Example:

```python
model.save_pretrained("./day173-lora-adapter")
```

Here:

- `model` is the trained PEFT model.
- `save_pretrained()` saves the adapter.
- `./day173-lora-adapter` is the output directory.

After execution, the adapter files should appear inside that directory.

**Important:** This assumes `model` is the trained PEFT model with the LoRA adapter attached.

Calling `save_pretrained()` on an ordinary base model does not automatically save a trained LoRA adapter.

# 6. Complete Adapter Saving Example

```python
import os

OUTPUT_DIR = "./day173-lora-adapter"

# Create the output directory
os.makedirs(OUTPUT_DIR, exist_ok=True)

# Save the trained LoRA adapter
model.save_pretrained(OUTPUT_DIR)

# Save the tokenizer
tokenizer.save_pretrained(OUTPUT_DIR)

print("LoRA adapter saved successfully!")
print("Location:", OUTPUT_DIR)
```

### What Does This Code Do?

**1. Import os**

Allows Python to work with directories and files.

**2. Define OUTPUT_DIR**

Specifies where the adapter should be saved.

**3. os.makedirs()**

Creates the output directory if it does not already exist.

**4. model.save_pretrained()**

Saves the trained LoRA adapter.

**5. tokenizer.save_pretrained()**

Saves the tokenizer configuration and associated files.

**6. print()**

Displays a confirmation message.

# 7. How to Verify the Saved Adapter

Saving a model is not enough.

We should verify that the expected files exist.

```python
import os

OUTPUT_DIR = "./day173-lora-adapter"

expected_files = [
    "adapter_config.json",
    "adapter_model.safetensors"
]

for file in expected_files:
    file_path = os.path.join(OUTPUT_DIR, file)

    if os.path.exists(file_path):
        print(f"FOUND: {file}")
    else:
        print(f"MISSING: {file}")
```

Expected output:

```text
FOUND: adapter_config.json
FOUND: adapter_model.safetensors
```

The exact files may vary depending on the saving configuration and library version.

# 8. How to Reload a Saved LoRA Adapter

One major advantage of LoRA is that we can load the adapter again later.

We need:

1. The original base model.
2. The saved LoRA adapter.
3. The correct tokenizer.

Example:

```python
import torch

from transformers import AutoTokenizer, AutoModelForCausalLM
from peft import PeftModel

BASE_MODEL = "Qwen/Qwen2.5-0.5B"
ADAPTER_PATH = "./day173-lora-adapter"

# Load tokenizer
tokenizer = AutoTokenizer.from_pretrained(BASE_MODEL)

# Load original base model
base_model = AutoModelForCausalLM.from_pretrained(
    BASE_MODEL,
    torch_dtype="auto"
)

# Load saved LoRA adapter
model = PeftModel.from_pretrained(
    base_model,
    ADAPTER_PATH
)

print("Base model and LoRA adapter loaded successfully!")
```

### Understanding the Code

`AutoTokenizer.from_pretrained()`

Loads the tokenizer associated with the base model.

`AutoModelForCausalLM.from_pretrained()`

Loads the original pretrained language model.

`PeftModel.from_pretrained()`

Loads the saved adapter and attaches it to the base model.

Now we can use the model for text generation without repeating fine-tuning.

**Important:** The base model and adapter must be compatible. The original model identifier and revision should be documented.

# 9. Saving vs Loading vs Training

These are three different operations.

| Operation | Purpose |
|---|---|
| Training | Updates the trainable adapter parameters. |
| Saving | Stores the trained adapter on disk. |
| Loading | Restores a previously saved adapter. |

Example workflow:

```text
Pretrained Base Model
        |
        v
Configure LoRA
        |
        v
Train LoRA Adapter
        |
        v
Save Adapter
        |
        v
Load Adapter Later
        |
        v
Generate Responses
```

We do not need to repeat training every time we want to use the saved adapter.

# 10. Saving Adapters in Google Colab

Google Colab provides temporary runtime storage.

If the runtime disconnects or resets, files stored only in the temporary environment may disappear.

We can use Google Drive for persistent storage.

### Mount Google Drive

```python
from google.colab import drive

drive.mount("/content/drive")
```

### Save the Adapter to Google Drive

```python
OUTPUT_DIR = "/content/drive/MyDrive/day173-lora-adapter"

model.save_pretrained(OUTPUT_DIR)
tokenizer.save_pretrained(OUTPUT_DIR)

print("Adapter saved to Google Drive!")
```

Now the adapter is stored in Google Drive rather than only in temporary Colab storage.

# 11. Adapter vs Full Model

| Feature | LoRA Adapter | Full Model |
|---|---|---|
| Contains original model weights | No | Yes |
| Contains trained parameters | Adapter parameters | Full model parameters |
| Storage requirement | Usually smaller | Usually larger |
| Requires original base model | Yes | Usually no |
| Easy to share separately | Yes | Yes |
| Suitable for parameter-efficient fine-tuning | Yes | Yes |

A LoRA adapter is generally much smaller than the full model because it stores only the learned adapter parameters.

# 12. Common Mistakes When Saving Adapters

### Mistake 1: Saving Before Training Finishes

If training has not completed, the saved adapter may not contain the final trained parameters.

### Mistake 2: Saving the Wrong Model

Make sure you save the PEFT model containing the trained adapter, not just the original base model.

### Mistake 3: Forgetting the Base Model Name

A LoRA adapter normally needs its compatible base model to work.

Record the base model identifier and revision.

### Mistake 4: Using Temporary Colab Storage

Files stored only in temporary runtime storage can disappear.

Use Google Drive or another persistent storage location.

### Mistake 5: Uploading Large Files to GitHub

Adapter weights can be binary files.

For larger experiments, use Google Drive or Hugging Face Hub rather than committing large weight files directly to a normal Git repository.

Keep configuration files, scripts and documentation in GitHub.
