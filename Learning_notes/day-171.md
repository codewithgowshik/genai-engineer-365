# 1. Learning Objective

Today's objective is to understand how to monitor model training and evaluate whether fine-tuning actually improves a model's performance.

We will learn:

- How to monitor training progress.
- What training loss and validation loss mean.
- How to identify overfitting and underfitting.
- How to compare a base model with a fine-tuned model.
- How to evaluate model responses using a test dataset.
- How to document evaluation results.

# 2. What Is Training Monitoring?

Training monitoring is the process of observing a machine learning model while it is being trained.

It helps us understand whether the model is learning correctly and whether the training process is stable.

We monitor several important metrics.

| Metric | Meaning |
|---|---|
| Training Loss | Measures the model's error on training data. |
| Validation Loss | Measures the model's error on unseen validation data. |
| Learning Rate | Controls the size of model parameter updates. |
| Training Steps | Number of optimiser updates completed. |
| Epochs | Number of complete passes through the training dataset. |
| Training Time | Time taken to complete training. |

Monitoring helps identify problems before training finishes.

# 3. Training Loss

Training loss measures how different the model's predictions are from the expected answers in the training dataset.

A lower training loss generally means the model is fitting its training examples better.

Example:

| Training Step | Training Loss |
|---|---:|
| 1 | 2.50 |
| 2 | 2.10 |
| 3 | 1.80 |
| 4 | 1.40 |
| 5 | 1.10 |

The loss decreases as training progresses.

This suggests that the model is learning patterns from its training examples.

However, training loss alone cannot tell us whether the model performs well on new examples.

# 4. Validation Loss

Validation loss measures the model's performance on a separate dataset that is not used to update its parameters.

Why is this important?

A model might memorise its training examples without learning patterns that generalise to new data.

Validation loss helps us detect this problem.

Example:

| Epoch | Training Loss | Validation Loss |
|---|---:|---:|
| 1 | 2.50 | 2.60 |
| 2 | 1.80 | 1.95 |
| 3 | 1.20 | 1.50 |
| 4 | 0.70 | 1.90 |
| 5 | 0.30 | 2.40 |

Training loss continues decreasing, but validation loss starts increasing.

This is a warning sign of overfitting.

# 5. Understanding Overfitting

Overfitting happens when a model learns the training examples too specifically and performs poorly on unseen examples.

For example:

Imagine training a model using 100 question-and-answer examples.

The model learns those examples very well.

However, when we ask a slightly different question, it struggles to produce a good answer.

This means the model has not generalised sufficiently.

### Signs of overfitting

- Training loss keeps decreasing.
- Validation loss starts increasing.
- Model performs well on training examples.
- Model performs poorly on unseen examples.

### Ways to reduce overfitting

- Use a more representative dataset.
- Remove duplicate examples.
- Avoid excessive training epochs.
- Monitor validation loss.
- Adjust learning rate and LoRA settings.
- Increase the quality and diversity of training examples.

# 6. Understanding Underfitting

Underfitting happens when a model has not learned the task sufficiently.

Signs include:

- High training loss.
- High validation loss.
- Poor performance on both training and unseen examples.

Possible solutions:

- Improve the quality of training data.
- Increase training time when appropriate.
- Adjust learning rate.
- Review LoRA rank and configuration.
- Check whether the training task is suitable for the selected model.

# 7. What Is Model Evaluation?

Model evaluation is the process of testing a trained model to determine how well it performs on a specific task.

Fine-tuning does not automatically make a model better.

We need evidence.

For this project, we compare:

**Model A: Base Model**

Qwen2.5-0.5B

**Model B: Fine-Tuned Model**

Qwen2.5-0.5B + LoRA adapter

Both models receive the same evaluation questions.

We then compare their responses.

# 8. Why Compare the Base Model and Fine-Tuned Model?

Imagine we want a model to explain technical concepts using simple English.

The original model might produce complicated explanations.

After fine-tuning, we want the model to produce simpler and more consistent explanations.

We need to check whether the fine-tuned model actually achieves this objective.

| Comparison | Base Model | Fine-Tuned Model |
|---|---|---|
| Model weights | Original pretrained weights | Original weights with trained adapter |
| Training | No additional task-specific training | LoRA fine-tuning |
| Task behaviour | Original behaviour | Potentially adapted behaviour |
| Evaluation | Same test dataset | Same test dataset |

The purpose is to measure the improvement caused by fine-tuning.

# 9. Evaluation Dataset

An evaluation dataset contains examples used to test model performance.

Each example should contain:

- Instruction
- Input
- Expected output

Example:

```json
{"instruction":"Explain artificial intelligence in simple words.","input":"","expected_output":"Artificial intelligence is technology that allows computers to perform tasks that normally require human intelligence."}
{"instruction":"What is machine learning?","input":"","expected_output":"Machine learning is a branch of artificial intelligence where computers learn patterns from data."}
{"instruction":"Explain what an API does.","input":"","expected_output":"An API allows different software applications to communicate and exchange information."}
```

### Important: Data Leakage

Data leakage happens when information from the evaluation or test dataset influences model training.

For reliable evaluation:

- Training data must remain separate.
- Validation data must remain separate.
- Test data must remain unseen during training and model selection.

A model should be evaluated using examples it has not already learned.

# 10. Evaluation Metrics

Different metrics help us understand different aspects of model performance.

| Metric | Meaning |
|---|---|
| Accuracy | Percentage of correct predictions. |
| Precision | How many predicted positive results were actually positive. |
| Recall | How many actual positive results were correctly identified. |
| F1 Score | Harmonic mean of precision and recall. |
| Exact Match | Whether the generated answer exactly matches the expected answer. |
| ROUGE | Measures word or phrase overlap with reference text. |
| BLEU | Measures n-gram overlap with reference text. |

Not every metric is suitable for every language task.

For open-ended question answering, exact text matching can be misleading because different answers may communicate the same meaning.

Human evaluation can help assess answer quality.

# 11. Human Evaluation

Human evaluation means a person reviews model-generated responses and judges their quality.

For our project, we can evaluate responses using five criteria.

| Criterion | Question |
|---|---|
| Accuracy | Is the answer factually correct? |
| Relevance | Does it answer the question? |
| Clarity | Is it easy to understand? |
| Completeness | Does it include important information? |
| Instruction Following | Does it follow the requested instruction? |

We can give each criterion a score from 1 to 5.

Example:

| Criterion | Base Model | Fine-Tuned Model |
|---|---:|---:|
| Accuracy | 4 | 4 |
| Relevance | 3 | 5 |
| Clarity | 2 | 5 |
| Completeness | 4 | 4 |
| Instruction Following | 3 | 5 |
| Average | 3.2 | 4.6 |

These are illustrative scores, not actual evaluation results.

# 12. The Evaluation Workflow

A typical fine-tuned model evaluation follows this process:

1. Load the original pretrained model.
2. Load the fine-tuned LoRA adapter.
3. Prepare an unseen evaluation dataset.
4. Send identical prompts to both models.
5. Generate responses using consistent settings.
6. Compare generated responses with expected answers.
7. Calculate relevant metrics.
8. Review response quality.
9. Document the results.
10. Decide whether fine-tuning improved performance.

### Important

Keep generation settings consistent:

- Temperature
- Maximum new tokens
- Sampling settings
- Prompt format
- Evaluation examples

Otherwise, differences in generation settings may affect the comparison.

# 13. Training Monitoring vs Model Evaluation

These concepts are related but serve different purposes.

| Training Monitoring | Model Evaluation |
|---|---|
| Observes training progress. | Measures model performance. |
| Happens during training. | Usually happens after training. |
| Monitors training and validation loss. | Tests responses on evaluation examples. |
| Helps identify training problems. | Helps determine whether the model achieved its objective. |
| Example: Loss curve. | Example: Base vs fine-tuned comparison. |

Monitoring tells us how training is progressing.

Evaluation tells us whether the resulting model is useful.
