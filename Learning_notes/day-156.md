## 1. Model parameters and model size

A model contains numerical values called **parameters**. These are learned during training and help the model process input and generate responses.

The letter **B** means billion:

| Model label | Approximate number of parameters |
|---|---:|
| 1B | 1 billion |
| 3B | 3 billion |
| 7B | 7 billion |
| 8B | 8 billion |
| 9B | 9 billion |
| 70B | 70 billion |

My installed models:
- `qwen3-vl:8b` — approximately 8 billion parameters.
- `qwen3.5:9b` — approximately 9 billion parameters.

A larger parameter count generally requires more memory to store model weights. It does not automatically mean the model performs better.

## 2. Why models need memory

Each parameter must be stored as a numerical value.

For a 9-billion-parameter model using 16-bit precision:
- 16 bits = 2 bytes.
- 9 billion × 2 bytes = approximately 18 GB for the weights alone.

Running a model also requires memory for context, KV cache, runtime operations and temporary calculations. Actual memory use is therefore higher than the weight-only estimate.

## 3. What is quantization?

**Quantization** reduces the numerical precision used to represent model weights.

It reduces the memory required to store and run a model, making local inference possible on hardware with less memory.

Example:
- Higher precision: `0.123456789`
- Lower precision: `0.12`

The lower-precision representation uses less information. Quantization can introduce some loss of accuracy, so there is a trade-off between memory use and model quality.

## 4. Precision formats

Approximate weight memory for a 9B-parameter model:

| Format | Bits per parameter | Approximate weight memory |
|---|---:|---:|
| FP32 | 32 bits | 36 GB |
| FP16 | 16 bits | 18 GB |
| INT8 | 8 bits | 9 GB |
| 4-bit | 4 bits | 4.5 GB |

These are simplified estimates for model weights only. Actual model files and runtime memory requirements vary with quantization format, metadata and model architecture.

## 5. Advantages and trade-offs

**Advantages**
- Reduces model memory requirements.
- Makes local inference possible on more modest hardware.
- Can make it practical to run larger models locally.

**Trade-offs**
- Lower precision can reduce response quality or accuracy.
- Excessive quantization can affect performance.

The aim is to reduce memory use while keeping model quality at an acceptable level.

## 6. Key terms

| Term | Meaning |
|---|---|
| Parameters | Numerical values learned during model training. |
| Model size | Often described by parameter count, such as 9B. |
| Precision | How numerical values are represented. |
| Quantization | Reducing numerical precision to reduce memory requirements. |
| Inference | Running a trained model to generate a response. |
| VRAM | Dedicated GPU memory. |
| RAM | System memory used by applications and model inference. |
| KV cache | Memory storing attention-related information from previous tokens to help process subsequent tokens. |

Model parameters are the learned numerical values inside a model. More parameters generally require more memory. Quantization reduces the precision used to store model weights, lowering memory requirements, with a possible trade-off in model quality.
