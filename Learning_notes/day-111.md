# Day 111 — Storytelling & End-to-End Testing

## Objective

Learn how to explain a project as a clear story and test the Semantic Search Engine from the beginning of the pipeline to the final user experience.

---

## 1. What is Storytelling in a Technical Project?

Technical storytelling means explaining a project as a clear journey instead of only listing technologies.

A simple structure is:

```text
Problem
  ↓
Solution
  ↓
How it works
  ↓
Result
```

For the Semantic Search Engine:

```text
Problem
  ↓
Users need to find relevant information
  ↓
Keyword search can depend heavily on exact words
  ↓
Build semantic search
  ↓
Documents → Embeddings → Vector Database
  ↓
User enters a query
  ↓
Query becomes an embedding
  ↓
Similar documents are retrieved
  ↓
Results are displayed in Streamlit
```

## 3. What Does End-to-End Testing Mean?

End-to-end testing means testing the complete application flow rather than testing only one individual function.

For this project:

```text
Sample Dataset
      ↓
   Ingestion
      ↓
   Embeddings
      ↓
    Chroma
      ↓
  Streamlit App
      ↓
  User Query
      ↓
Query Embedding
      ↓
Similarity Search
      ↓
  Top-K Results
      ↓
 Results Displayed
```

The goal is to confirm that all the parts work together as one complete product.

---

## 4. End-to-End Test Steps

### Step 1 — Test Ingestion

Run:

```bash
python src/ingest.py
```

Check that the sample documents are successfully stored.

### Step 2 — Start the Application

Run:

```bash
streamlit run app.py
```

Open the Streamlit application.

### Step 3 — Test Multiple Queries

Test several different queries instead of only one.

Example queries:

```text
How do computers learn?
```

Expected topic: machine learning.

```text
How can I search information by meaning?
```

Expected topic: semantic search.

```text
What stores numerical representations?
```

Expected topic: vector databases or embeddings.

```text
How can I build a Python web interface?
```

Expected topic: Streamlit.

```text
What is the capital city of Britain?
```

Expected topic: London.

---

## 5. What Should Be Tested?

| Component | Test |
|---|---|
| Dataset | Can the application access the sample documents? |
| Ingestion | Are documents stored successfully? |
| Embeddings | Can text be converted into vectors? |
| Chroma | Can stored documents be searched? |
| Query embedding | Can the user's query be converted into a vector? |
| Semantic search | Are meaningfully related documents retrieved? |
| Top-K | Does the selected number of results work? |
| Streamlit | Does the UI work? |
| Empty query | Does the app handle an empty search? |
| Multiple queries | Does the system continue working after repeated searches? |

---

## 6. Test the Failure Case

Enter an empty query and press Search.

The application should handle the input without crashing and show a warning such as:

```text
Please enter a search query.
```

This checks that the application can handle invalid or incomplete user input.

## 8. What I Learned

- Technical storytelling explains a project through a clear problem-to-solution journey.
- A project should be explained by what problem it solves, how it works, and what result it produces.
- End-to-end testing checks the complete application flow.
- Testing multiple queries helps verify that the search system works beyond a single example.
- Failure cases such as an empty query are also important to test.
