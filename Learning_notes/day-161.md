# 2. What Are Open-Weight Models?

Open-weight models are AI models whose trained weights are publicly available for developers to download and use, subject to their individual licences.

Developers can use them to:

- Build AI applications.
- Run models locally.
- Deploy models on private infrastructure.
- Customise model behaviour.
- Fine-tune models.
- Experiment with different configurations.

Unlike hosted AI services, open-weight models give developers more control over how and where models are deployed.

### Examples of Open-Weight Models

| Model Family | Developer |
|---|---|
| Llama | Meta |
| Qwen | Alibaba |
| Mistral | Mistral AI |
| Gemma | Google |
| DeepSeek | DeepSeek |

**Important:** Open-weight does not automatically mean open-source. Model weights, training data, source code and licensing are separate considerations.

# 3. Open-Weight Models vs Closed Models

There are two common approaches to using LLMs.

### A. Closed Models

Closed models are generally accessed through APIs or hosted platforms.

Examples include proprietary models from commercial AI providers.

Advantages:

- Easy API integration.
- No need to manage model infrastructure.
- Managed deployment.
- Access to powerful models.

Disadvantages:

- API costs.
- Dependence on external providers.
- Less control over infrastructure.
- Data handling depends on provider policies.

### B. Open-Weight Models

Developers can download model weights and run supported models using their own infrastructure.

Advantages:

- Greater deployment flexibility.
- Local inference capabilities.
- More control over infrastructure.
- Ability to customise supported models.
- Potentially lower operating costs at scale.

Disadvantages:

- Hardware requirements.
- Infrastructure management.
- Model optimisation.
- Performance monitoring.
- Responsibility for deployment security.

### Comparison

| Feature | Open-Weight Models | Closed Models |
|---|---|---|
| Model weights | Available under licence | Generally unavailable |
| Local deployment | Often possible | Generally unavailable |
| Infrastructure control | Greater | Limited |
| API availability | Depends on deployment | Usually available |
| Customisation | Depends on licence and model | Generally limited |
| Maintenance | Developer responsibility | Provider responsibility |

# 4. Understanding Model Parameters

Parameters are the numerical values learned during model training.

They represent the learned relationships and patterns that allow a neural network to process information and generate responses.

Model sizes are commonly described using parameter counts.

Examples:

- 1B = 1 billion parameters.
- 3B = 3 billion parameters.
- 7B = 7 billion parameters.
- 8B = 8 billion parameters.
- 70B = 70 billion parameters.

### Why Does Model Size Matter?

Model size influences:

- Memory requirements.
- Computational requirements.
- Inference performance.
- Deployment costs.

Generally, larger models require more resources.

However, a larger model does not automatically perform better on every task.

Architecture, training quality, data, quantization and task-specific capabilities also matter.

### Example

| Model Size | General Resource Requirement |
|---|---|
| 1B | Low |
| 3B | Relatively low |
| 7B | Moderate |
| 8B | Moderate |
| 70B | High |

These are relative comparisons, not fixed hardware requirements.

# 5. Understanding Hardware Requirements

Before selecting a model, developers must understand whether their hardware can run it.

Important hardware components include:

### A. CPU

The Central Processing Unit executes general-purpose computational operations.

Models can run using CPU inference, although performance may be slower than suitable GPU configurations.

### B. GPU

The Graphics Processing Unit accelerates the mathematical operations used during neural network inference.

GPUs are commonly used for faster LLM execution.

### C. VRAM

Video RAM is memory available on a GPU.

It stores model weights and other inference data.

Insufficient VRAM can prevent a model from fitting entirely on the GPU, resulting in partial CPU offloading or execution failures.

### D. RAM

System RAM provides memory for running applications and can also be used for model execution.

### E. Storage

Model files can occupy several gigabytes or more.

Sufficient storage is necessary when downloading multiple models.

**Key takeaway:** Always check memory requirements before downloading and deploying a model.

# 6. Understanding Context Windows

A context window represents the maximum number of tokens a model can process within a single interaction.

It includes relevant input and generated output tokens.

For example:

| Context Window | Approximate Capacity |
|---|---:|
| 4K | 4,096 tokens |
| 8K | 8,192 tokens |
| 32K | 32,768 tokens |
| 128K | 131,072 tokens |

### Why Is Context Length Important?

Imagine building a document summarisation application.

A user uploads a long document containing 20,000 tokens.

A model with a 4K context window cannot process the entire document in one request.

A model with a sufficiently large context window may be able to process it.

Applications involving:

- Long documents.
- Large conversations.
- Code repositories.
- Retrieval-Augmented Generation (RAG).
- Document analysis.

may benefit from larger context windows.

However, a larger context window can increase memory consumption and computational costs.

# 7. Understanding Quantization

Quantization is a technique that reduces the numerical precision used to represent model weights.

It helps reduce memory requirements and can improve inference efficiency.

### Common Numerical Formats

| Format | Precision |
|---|---:|
| FP32 | 32-bit floating point |
| FP16 | 16-bit floating point |
| BF16 | 16-bit floating point |
| INT8 | 8-bit integer |
| INT4 | 4-bit integer |

### Example

Consider a hypothetical model with 7 billion parameters.

If each parameter is stored using 16 bits:

```text
7 billion × 16 bits

= 112 billion bits

= Approximately 14 GB
```

If each parameter is stored using 4 bits:

```text
7 billion × 4 bits

= 28 billion bits

= Approximately 3.5 GB
```

These are theoretical weight-storage estimates using decimal units. Actual memory requirements are higher because of metadata, runtime overhead, KV cache and other allocations.

### Benefits of Quantization

- Reduces model memory requirements.
- Makes larger models easier to deploy.
- Can improve inference efficiency.
- Reduces hardware requirements.

### Disadvantages

- Can reduce response quality.
- May affect reasoning accuracy.
- Different quantization methods produce different results.

**Key takeaway:** Quantization helps developers run models with limited hardware resources, but performance and quality should be tested.

# 8. Understanding Inference Performance

A model's performance is not determined by its size alone.

Developers must measure how efficiently it generates responses.

Important performance metrics include:

### A. Latency

The time taken to receive a response after submitting a request.

### B. Time to First Token (TTFT)

The time taken to receive the first generated token.

### C. Tokens Per Second (TPS)

The number of generated tokens per second.

Formula:

```text
TPS = Generated Tokens / Generation Time
```

### D. Throughput

The total amount of work processed within a given period.

These metrics help developers evaluate whether a model is suitable for their application.

### Connection to Day 160

On Day 160, I learned how to benchmark local model latency.

That knowledge is useful when comparing multiple open-weight models.

For example:

| Metric | Model A | Model B |
|---|---:|---:|
| Average latency | 1.5 seconds | 3 seconds |
| Tokens per second | 45 | 25 |
| Context window | 8K | 32K |

Model A is faster in this example, while Model B supports a larger context window.

The correct choice depends on the application's requirements.

# 9. Understanding Model Licensing

Model licensing is one of the most important factors when choosing an open-weight model.

A model being publicly downloadable does not automatically mean it can be used commercially without restrictions.

Before using a model, check:

1. Commercial usage permissions.
2. Redistribution restrictions.
3. Modification permissions.
4. Attribution requirements.
5. Acceptable-use policies.
6. Additional licence conditions.

### Why Is Licensing Important?

Imagine developing a commercial AI application.

You select a model and integrate it into your product.

Later, you discover that its licence restricts your intended commercial use.

This can create legal and business problems.

Therefore, always review the specific model licence before using it in production.

# 12. Practical Model Selection Example

Imagine developing a customer-support chatbot.

### Application Requirements

- Answer customer questions.
- Generate responses quickly.
- Support multiple conversations.
- Run on available infrastructure.
- Produce accurate and relevant answers.

Consider three candidate models.

| Criteria | Model A | Model B | Model C |
|---|---|---|---|
| Parameters | 1B | 3B | 8B |
| Resource requirements | Low | Medium | Higher |
| Expected speed | Faster | Moderate | Potentially slower |
| Complex reasoning | More limited | Moderate | Potentially stronger |
| Deployment difficulty | Lower | Moderate | Higher |

### Which Model Should We Select?

We should not automatically select Model C because it has the most parameters.

Instead:

1. Test all three models using identical prompts.
2. Measure average latency.
3. Measure tokens per second.
4. Evaluate answer accuracy.
5. Check hardware utilisation.
6. Compare model licences.
7. Select the model that satisfies the application's requirements.

The best model is not necessarily the largest or fastest model.

It is the model that provides the best balance between quality, performance, cost and deployment requirements.
