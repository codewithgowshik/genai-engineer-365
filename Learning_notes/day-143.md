## Goal

Improve the RAG app so it ranks retrieved passages by relevance and includes source citations with generated answers.

## LEARN — Streaming Answers

Streaming means returning an answer a little at a time as the model generates it, rather than waiting for the entire response.

- **Normal response:** the app waits for generation to finish, then displays the complete answer.
- **Streaming response:** the app yields chunks of generated text as they become available.
- **User experience:** streaming can make an app feel faster, even when total generation time is similar.
- **RAG flow:** retrieve relevant passages, prepare the prompt with those passages, then stream the model's answer.
- **Important:** citations still need to be grounded in retrieved source passages. Streaming does not make an unsupported citation reliable.

For today's build, focus on reranking and citations first. Streaming can be added to the generation layer when that layer is implemented.

## BUILD — Add Reranking and Citations

### 1. Add a reranking step

Vector similarity retrieves candidate chunks. Reranking is a second pass that scores those candidates against the user's query and reorders them by relevance.

Suggested flow:

1. Embed the user's query.
2. Retrieve a wider set of candidates from ChromaDB (for example, top 10).
3. Rerank the candidates against the query.
4. Keep the best few passages (for example, top 3) as context for generation.
5. Preserve each passage's source metadata so citations can be attached to the answer.

Use a cross-encoder reranker from `sentence-transformers` if it fits the existing project setup. Keep the implementation simple and easy to test.

### 2. Preserve citation metadata

Each indexed chunk should carry metadata identifying where it came from, such as:

- `source`: source filename or document name
- `chunk_id`: stable identifier for the chunk
- `page`: page number, if the source has pages

For the current text-file prototype, `source` and `chunk_id` are sufficient. Do not invent page numbers if the source has none.

### 3. Return sources with retrieval results

Update `src/retrieval.py` so each passage result includes its text, source metadata, and similarity distance or reranker score where useful. Keep metadata attached through the pipeline; do not discard it after reranking.

### 4. Prepare citation-ready answers

When generation is added, instruct the model to answer using only the supplied context and cite source IDs next to supported claims, for example `[1]`.

Example format:

```text
Answer:
Customers can request a refund within the stated refund window [1].

Sources:
[1] refund_policy.txt — chunk 2
```

This is an illustrative format only. Use claims supported by the actual indexed documents; the sample policies in this project are fictional.

### 5. Test the change

- Run ingestion and retrieval.
- Ask a question that should match a known document.
- Compare the original retrieval order with the reranked order.
- Check that each returned passage retains its source and chunk ID.
- Confirm that the source list refers only to passages actually retrieved and used.
- Record any case where reranking makes results worse.

## Key Takeaways

- Vector retrieval finds candidate passages; reranking improves their order for a specific query.
- Citation metadata must travel with each chunk through retrieval and reranking.
- Citations should point only to sources actually used to support the answer.
- Streaming is a delivery technique, not a substitute for retrieval quality or grounding.
