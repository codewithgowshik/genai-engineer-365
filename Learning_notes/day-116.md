## Document Loading

Document loading is the process of bringing information from a source into the application so it can be processed.

In this project, the source is `data/documents.txt`. The loading process reads the file and turns its contents into documents that can later be chunked, embedded, stored, and retrieved.

The basic preparation flow is:

```text
documents.txt
      ↓
Load
      ↓
Documents
      ↓
Chunk
      ↓
Embed
      ↓
Store
```

Document loading and retrieval are different stages. Loading happens while preparing the dataset, while retrieval happens later when a user asks a question.

## Retrieving Relevant Chunks

After the chunks and their embeddings have been stored in Chroma, the system can retrieve information when a user submits a query.

The user's question is converted into an embedding and compared with the stored vectors.

The retrieval flow is:

```text
User Question
      ↓
Query Embedding
      ↓
Chroma
      ↓
Relevant Chunks
```

The goal is not to retrieve every document. The goal is to retrieve the chunks that are most relevant to the user's question.

For example, if the question is "How do computers learn from data?", a relevant chunk might be: "Machine learning allows computers to learn patterns from data."

## Top-K Retrieval

Project 3 introduced Top-K retrieval. The same concept is now being used as part of the RAG pipeline.

If `k = 3`, the retrieval system attempts to return the three most relevant chunks for the query.

```text
User Query
    ↓
Similarity Search
    ↓
Top-K Chunks
```

This allows the RAG system to control how much retrieved information is passed to the next stage.

## Building the Context

After retrieving the relevant chunks, the next step is to combine them into a single piece of context.

For example, the retriever might return multiple relevant chunks. These chunks can be joined together to create the context that will be provided to the language model.

The important idea is that the retrieved documents are no longer only displayed as search results. They are prepared as information that the LLM can use.

## Context Injection

Context injection means putting the retrieved information into the prompt together with the user's question.

A simple RAG prompt can look like:

```text
Context:
Machine learning allows computers to learn patterns from data.

Question:
How do computers learn from data?

Answer using the provided context.
```

The retrieved information is now available to the LLM when it generates the answer. This is the bridge between retrieval and generation.
