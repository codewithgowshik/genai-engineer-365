## 1. What is a no-answer case?

A RAG system retrieves passages from a knowledge base and uses them to generate an answer. Retrieval does not guarantee that the passages contain enough evidence to answer the question.

For example, if the documents explain a refund policy, the system can answer a question about refunds. If the documents do not mention the CEO’s birthday, the system should not invent a date.

A suitable fallback is:

> I couldn’t find enough information in the available documents to answer that question accurately.

## 2. Key concept: Abstention

**Abstention** means declining to provide an answer when the available evidence is insufficient.

| Situation | Expected behaviour |
|---|---|
| Relevant evidence supports the answer | Answer using the passages and cite them |
| Evidence answers only part of the question | Answer the supported part and explain what is missing |
| No relevant evidence is available | Say that the documents do not provide enough information |

A plausible answer is not necessarily a supported answer.

## 3. Retrieval scores are not certainty

The project retrieves candidate passages from ChromaDB and reranks them with a cross-encoder. A reranker score is a relevance signal; it is **not** a calibrated probability that an answer is correct.

A passage may be related to a question without containing the answer. For this reason, use retrieval checks and clear generation instructions rather than treating a high score as proof.

## 4. Implementation notes

### Handle empty retrieval results

In `src/generation.py`, check for an empty passage list before building the context or calling Gemini:

```python
if not passages:
    yield "I couldn't find relevant information in the available documents."
    return
```

This handles the case where retrieval returns no passages. It does not handle every case where passages exist but do not answer the question.

### Instruct Gemini to stay grounded

Use a prompt that explicitly tells Gemini to:

- Answer only with information supported by the supplied passages.
- Never invent facts, dates, names, policies, or statistics.
- Acknowledge when the passages do not contain enough information.
- Answer supported parts of a question while identifying what remains unknown.
- Cite supporting passages using their citation numbers, such as `[1]`.
- Avoid claiming that a source supports something it does not state.

**Limitation:** Prompt instructions reduce unsupported answers but do not guarantee perfect abstention. Test the system with real questions and inspect its responses.

## 5. Testing plan

Run the backend and test through the React chat UI.

### Test A — Answerable question

Ask a question whose answer is explicitly present in `data/documents.txt`.

**Expected:** An answer supported by the retrieved passages, with appropriate citation numbers.

### Test B — Unanswerable question

Ask a question about information that is not present in the documents, such as the CEO’s birthday, provided the documents do not contain that detail.

**Expected:** The system acknowledges that the information is unavailable instead of inventing an answer.

### Test C — Partially answerable question

Ask a question with one part supported by the documents and another part not covered.

**Expected:** The system answers the supported part and acknowledges what cannot be established from the available evidence.

Record the actual results; do not mark a test as passed until you have run it.
