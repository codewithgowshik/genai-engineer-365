# 2. What Is Overfitting?

Overfitting happens when a machine learning model learns the training examples too specifically instead of learning patterns that generalise to new examples.

In simple words:

**The model memorises instead of learning how to handle unfamiliar examples.**

Imagine training a language model using 100 examples of technical questions.

During training, the model becomes very good at answering those specific questions.

However, when we ask a slightly different question, its answer quality becomes worse.

This is a sign of possible overfitting.

# 3. Overfitting in Fine-Tuning

Fine-tuning adapts a pretrained model to a particular task using additional training data.

However, if the dataset is too small, repetitive or narrow, the model may become overly specialised.

For example:

Original model:
- Explains programming concepts.
- Answers general questions.
- Understands different writing styles.

After excessive fine-tuning on a small dataset:
- Performs well on familiar examples.
- Repeats similar answers.
- Struggles with unfamiliar questions.
- May lose some general-purpose capabilities.

This is why evaluating a fine-tuned model is important.

# 4. Why Does Overfitting Happen?

Several factors can contribute to overfitting.

| Cause | Explanation |
|---|---|
| Small dataset | The model sees too few examples. |
| Duplicate data | The model repeatedly learns similar examples. |
| Too many epochs | The model trains for longer than necessary. |
| High learning rate | Updates may be too aggressive. |
| Poor dataset quality | Incorrect or inconsistent examples affect learning. |
| Narrow dataset | The training data does not represent different situations. |
| Excessive model capacity | The adaptation may have more capacity than the dataset requires. |

Not every fine-tuning problem is overfitting. Poor results can also come from incorrect data formatting, unsuitable prompts or training configuration.

# 5. How to Identify Overfitting

The most common method is comparing training loss and validation loss.

Example:

| Epoch | Training Loss | Validation Loss |
|---|---:|---:|
| 1 | 2.50 | 2.60 |
| 2 | 1.90 | 2.00 |
| 3 | 1.30 | 1.50 |
| 4 | 0.80 | 1.90 |
| 5 | 0.40 | 2.40 |

What do we observe?

- Training loss continues decreasing.
- Validation loss initially decreases.
- Validation loss starts increasing after Epoch 3.

This suggests the model may be overfitting.

### Important

A training loss decrease does not guarantee better performance on unseen data.

We should monitor validation performance and evaluate the final model on a separate test dataset.

# 6. Ways to Reduce Overfitting

### 1. Improve Dataset Quality

Use accurate, diverse and relevant training examples.

Remove:
- Duplicate examples.
- Empty examples.
- Incorrect answers.
- Poorly formatted records.

### 2. Reduce Training Epochs

Too many training epochs can cause the model to overfit.

Test different epoch counts and compare validation performance.

### 3. Adjust Learning Rate

A learning rate that is too high can cause unstable training.

A lower learning rate may produce more controlled updates, although the best value depends on the model and dataset.

### 4. Use LoRA Dropout

LoRA includes a dropout parameter.

Example:

```python
from peft import LoraConfig, TaskType

lora_config = LoraConfig(
    r=8,
    lora_alpha=16,
    lora_dropout=0.05,
    target_modules=[
        "q_proj",
        "k_proj",
        "v_proj",
        "o_proj"
    ],
    bias="none",
    task_type=TaskType.CAUSAL_LM
)
```

Here:

- `r=8`: Low-rank dimension.
- `lora_alpha=16`: Scaling factor.
- `lora_dropout=0.05`: Applies dropout to LoRA input during training.

Dropout can help reduce overfitting, but it does not guarantee that overfitting will disappear.

### 5. Use Validation Data

Evaluate the model during training using separate validation examples.

This helps identify when performance stops improving.

# 7. What Is Catastrophic Forgetting?

Catastrophic forgetting happens when a model loses some previously learned capabilities while adapting to a new task.

Example:

Before fine-tuning:
- Answers general questions.
- Explains programming concepts.
- Summarises documents.

After narrow fine-tuning:
- Performs well on the specialised task.
- Becomes worse at some general tasks.

This is different from ordinary overfitting, although the two can occur together.

### Overfitting vs Catastrophic Forgetting

| Overfitting | Catastrophic Forgetting |
|---|---|
| Model fits training examples too closely. | Model loses previously learned capabilities. |
| Poor generalisation to unseen examples. | Reduced performance on previously learned tasks. |
| Often related to dataset size, diversity and training duration. | Often related to how new training affects existing capabilities. |

# 8. What Is a Base Model?

A base model is the original pretrained model before our additional fine-tuning.

For our project:

**Base Model:**

`Qwen/Qwen2.5-0.5B`

It contains the original pretrained model weights.

It has not been modified by our Day 169 LoRA training.

# 9. What Is a Fine-Tuned Model?

A fine-tuned model is a pretrained model that has been adapted through additional training.

In our project:

**Fine-Tuned Model:**

`Qwen/Qwen2.5-0.5B + LoRA Adapter`

The original base model is combined with the trained LoRA adapter during inference.

The adapter contains the learned parameter updates.

### Important Difference

With LoRA, we generally do not modify all the original model weights.

Instead, we train smaller adapter parameters and combine their effects with the frozen base model.

# 10. Why Compare the Base Model and Fine-Tuned Model?

Fine-tuning is only useful if it improves the intended task without causing unacceptable performance degradation.

For example, suppose our objective is to make a model explain technical concepts using simple English.

We want to find out:

- Does the fine-tuned model follow instructions better?
- Are its explanations clearer?
- Is its output more consistent?
- Does it maintain factual accuracy?
- Has it lost useful general capabilities?

We cannot answer these questions by looking only at training loss.

We need actual model comparisons.

# 11. Base Model vs Fine-Tuned Model

| Feature | Base Model | Fine-Tuned Model |
|---|---|---|
| Original pretrained weights | Yes | Yes |
| LoRA adapter | No | Yes |
| Additional task-specific training | No | Yes |
| Specialised task behaviour | Original behaviour | Potentially improved |
| General capabilities | Original capabilities | Must be tested |
| Model evaluation | Required | Required |

# 12. Practical Comparison Example

Imagine we give both models the same question:

**Question:**

"Explain machine learning to a complete beginner."

Example responses:

### Base Model

"Machine learning is a subfield of artificial intelligence that involves algorithms learning statistical patterns from datasets to make predictions."

### Fine-Tuned Model

"Machine learning is a way for computers to learn from examples. Instead of programming every rule, we give the computer data so it can find patterns and make predictions."

The fine-tuned response may be more suitable if our training objective was to produce beginner-friendly explanations.

However, this is only an illustrative example.

We must use actual generated responses to determine whether our model improved.

# 13. How to Compare Both Models Fairly

A reliable comparison requires controlled testing.

Follow these steps:

1. Load the original base model.
2. Load the same base model with the trained LoRA adapter.
3. Prepare an evaluation dataset that was not used for training.
4. Give both models identical questions.
5. Use the same generation settings.
6. Save both generated responses.
7. Compare their accuracy, clarity and relevance.
8. Test general capabilities separately.
9. Record the results.

### Keep These Settings Consistent

| Setting | Why It Matters |
|---|---|
| Temperature | Controls randomness in generation. |
| Max New Tokens | Controls response length. |
| Prompt | Ensures both models receive identical instructions. |
| Sampling Settings | Controls how tokens are selected. |
| Evaluation Dataset | Ensures both models answer the same questions. |

# 14. Evaluation Scorecard

We can use a simple scorecard to compare the models.

Score each criterion from 1 to 5.

| Criterion | Base Model | Fine-Tuned Model |
|---|---:|---:|
| Accuracy | 4 | 4 |
| Relevance | 3 | 5 |
| Clarity | 3 | 5 |
| Completeness | 4 | 4 |
| Instruction Following | 3 | 5 |
| Average | 3.4 | 4.6 |

These are illustrative scores, not actual experimental results.

### Interpreting Results

- Higher fine-tuned scores suggest improvement in the evaluated criteria.
- Similar scores suggest limited measurable improvement.
- Lower fine-tuned scores suggest possible regression.

A scorecard should be based on actual outputs and a consistent evaluation rubric.

# 15. General Capability Testing

A specialised fine-tuned model should not only perform well on its training task.

We should also check whether it can still handle unrelated tasks.

For example:

| Test Category | Example |
|---|---|
| General Knowledge | Explain how photosynthesis works. |
| Reasoning | Explain why the sky appears blue. |
| Programming | Explain what a Python function does. |
| Summarisation | Summarise a short paragraph. |
| Instruction Following | Explain a concept in three sentences. |

This helps identify possible capability degradation.

# 17. Training Monitoring vs Model Comparison

| Training Monitoring | Model Comparison |
|---|---|
| Observes training behaviour. | Compares model performance. |
| Uses training and validation loss. | Uses generated responses and evaluation metrics. |
| Helps detect overfitting. | Helps identify improvements and regressions. |
| Happens during training. | Happens during model evaluation. |

Both are important for building reliable fine-tuned models.
