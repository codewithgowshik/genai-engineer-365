## Retrieve → Augment → Generate

RAG stands for Retrieval-Augmented Generation. The basic flow can be understood as three stages: Retrieve, Augment, and Generate.

The first stage is **Retrieve**. Retrieval means finding information that is relevant to the user's question. The retriever's job is to find useful information; it does not generate the final answer.

For example, if the user asks, "How do computers learn?", the retrieval system might find a document such as:

```text
Machine learning allows computers to learn patterns from data.
```

The second stage is **Augment**. Augmentation means adding the retrieved information to the user's question as context before sending it to the language model.

The context and question can look like:

```text
Context:
Machine learning allows computers to learn patterns from data.

Question:
How do computers learn?
```

The third stage is **Generate**. The language model receives the question together with the retrieved context and generates a natural-language answer.

The complete flow is:

```text
Documents
    ↓
Load
    ↓
Chunk
    ↓
Embed
    ↓
Store
    ↓
Retrieve
    ↓
Relevant Chunks
    ↓
Augment
    ↓
Question + Context
    ↓
Generate
    ↓
Answer
```

The key idea is:

> Retrieve = find information.
>
> Augment = add the information as context.
>
> Generate = produce the answer.

## Chunking Documents

After loading the documents, the next step is chunking.

Chunking means dividing a larger piece of text into smaller pieces. This is useful because a large document may contain a lot of information, while only a small part of that document may be relevant to a particular question.

Instead of treating an entire large document as one piece:

```text
Large Document
      ↓
One large piece
```

we can divide it into:

```text
Large Document
      ↓
Chunk 1
Chunk 2
Chunk 3
Chunk 4
```

Each chunk can later be embedded and retrieved independently.

## Why Chunking Matters for RAG

Chunking is important because retrieval needs useful pieces of information.

If chunks are too large, the retrieved context may contain a lot of unnecessary information.

If chunks are too small, important context may be lost.

This means chunk size can affect retrieval quality. There is no single chunk size that is automatically correct for every dataset or application.
