## Prompt Templates for RAG

A prompt template is a reusable structure for creating prompts. Instead of writing a completely new prompt every time a user asks a question, the application keeps a standard prompt and fills in values such as the retrieved context and the user's question.

A simple RAG prompt template can look like this:

```text
Use the following context to answer the question.

Context:
{context}

Question:
{question}

Answer using only the provided context.
If the answer cannot be found in the context, say that the information is not available.
```

The `{context}` placeholder is replaced with the information retrieved from the vector database. The `{question}` placeholder is replaced with the user's actual question.

Using a template makes the RAG process more consistent because the application can use the same instructions for different questions.

## Why Prompt Templates Matter in RAG

A RAG system needs to clearly tell the language model what information it should use. The prompt template provides that structure.

The basic flow is:

```text
User Question
      ↓
Retrieve Relevant Chunks
      ↓
Insert Chunks into Prompt Template
      ↓
Insert User Question
      ↓
Send Prompt to LLM
      ↓
Generate Grounded Answer
```

The prompt therefore connects the retrieval stage with the generation stage.

## Source Citations

Today I also added source citations to the RAG workflow.

Previously, the pipeline looked like:

```text
Question
   ↓
Retrieve Chunks
   ↓
Build Context
   ↓
LLM
   ↓
Answer
```

After today's change, the system keeps the source information from the retrieved results:

```text
Question
   ↓
Retrieve Chunks
   ↓
Keep Chunk IDs / Source Information
   ↓
Build Context
   ↓
LLM
   ↓
Answer + Sources
```

The important idea is that the text used as context and the information identifying its source should be kept together during retrieval.

## Why Source Citations Are Useful

A generated answer can be easier to understand and trust when the application also shows where the supporting information came from.

For example, instead of displaying only:

```text
Machine learning allows computers to learn patterns from data.
```

the application can display:

```text
Machine learning allows computers to learn patterns from data.

Sources:
- chunk3
- chunk7
```

The source identifiers in this example represent the retrieved chunks that were used to provide context to the LLM.

## Keeping Source Information During Retrieval

When retrieving information from the vector database, the system receives both the document text and identifiers for the retrieved results.

Conceptually:

```python
results = retrieve(query)

documents = results["documents"][0]
ids = results["ids"][0]

context = "\n\n".join(documents)

answer = generate_answer(context, query)

print("Answer:")
print(answer)

print("\nSources:")
for source_id in ids:
    print("-", source_id)
```

The important part is that the application does not throw away the IDs after retrieving the documents. The document text is used to build the context, while the IDs remain available for displaying the sources.

## Example

Suppose the user asks:

```text
How do computers learn from data?
```

The retriever might return a chunk such as:

```text
Machine learning allows computers to learn patterns from data and make predictions.
```

The chunk is added to the context and the source ID is preserved.

The LLM then generates an answer using the retrieved context, while the application can display the corresponding source ID underneath the answer.

The result becomes:

```text
Answer:
Machine learning allows computers to learn patterns from data and use those patterns to make predictions.

Sources:
- chunk2
```

The exact generated wording may differ, but the source remains connected to the retrieved information.
