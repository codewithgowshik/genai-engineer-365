# Day 109 — Hosting & Project Screenshots

## Objective

Learn how a Streamlit application can be hosted online using Streamlit Community Cloud and improve the project's GitHub README by adding screenshots.

## 1. What is Hosting?

When the app runs on your own computer, it is usually available only through a local address such as:

```text
http://localhost:8501
```

**Hosting** means running the application on a remote server so other people can access it through the internet.

### Simple mental model

```text
Your computer
     ↓
   Code
     ↓
   GitHub
     ↓
Streamlit Community Cloud
     ↓
 Public web application
```

Local development is where you build and test the application. Hosting is the step that makes the application accessible online.

## 2. What is Streamlit Community Cloud?

Streamlit Community Cloud is a hosting platform for Streamlit applications. A typical workflow is:

1. Keep the Streamlit project in a GitHub repository.
2. Connect the repository to Streamlit Community Cloud.
3. Select the application entry file, such as `app.py`.
4. The platform installs the project's dependencies.
5. The Streamlit application is launched and made accessible through a web URL.

The important idea is that the application code remains in GitHub while the hosting platform runs the application for users.

## 3. Why Deployment Matters

A project that only runs on your laptop is difficult for someone else to try.

Deployment changes the project from:

```text
"Here is my code. You can run it yourself."
```

to:

```text
"Here is the application. Try it online."
```

For a portfolio project, this makes the result easier to demonstrate.

## 4. What are Screenshots?

Screenshots are images showing the application in action.

For the Semantic Search Engine, useful screenshots include:

- Main application interface
- A search query with results
- Number-of-results selection/filtering
- Empty-search or empty-result state

You do not need many screenshots. Around **2–3 strong screenshots** are enough to communicate how the application works.

## 5. Add an Images Folder

Create an `images` folder in the project:

```text
semantic-search-engine/
├── app.py
├── README.md
├── ARCHITECTURE.md
├── data/
├── src/
├── tests/
└── images/
    ├── main-ui.png
    ├── search-results.png
    └── filters.png
```

Place the screenshots inside this folder.

## 6. Adding Screenshots to README.md

Markdown can display an image using:

```markdown
![Semantic Search Engine UI](images/main-ui.png)
```

The first part is alternative text describing the image. The second part is the relative path to the image inside the repository.

For example:

```markdown
## Demo

![Semantic Search Engine UI](images/main-ui.png)

![Search Results](images/search-results.png)
```

Because the images are stored inside the GitHub repository, the README can display them when someone views the project.

## 7. Recommended README Structure

A simple structure for the project is:

```text
Project title
↓
Project overview
↓
Screenshots / Demo
↓
Architecture
↓
Features
↓
How it works
↓
Tech stack
↓
Installation
↓
Usage
↓
Evaluation
```

Putting screenshots near the beginning helps a visitor understand the project before reading the technical details.

## 8. Today's Build

Today's build is mainly about project presentation and shipping.

### Step 1 — Run the application

Start the Streamlit application locally:

```bash
streamlit run app.py
```

### Step 2 — Capture the main UI

Take a screenshot showing the main Semantic Search Engine interface.

Save it as:

```text
images/main-ui.png
```

### Step 3 — Capture search results

Enter a meaningful query and capture the returned results.

Save it as:

```text
images/search-results.png
```

### Step 4 — Capture filtering/results count

Show the number-of-results selection and the resulting output if useful.

Save it as:

```text
images/filters.png
```

### Step 5 — Add the images to README.md

Use relative Markdown paths:

```markdown
## Screenshots

![Main UI](images/main-ui.png)

![Search Results](images/search-results.png)

![Filters](images/filters.png)
```
