# Day 131 — Re-order Context to Reduce Middle Loss

## Objective

Understand the lost-in-the-middle problem and experiment with re-ordering retrieved context before sending it to an LLM.

## What Is the Lost-in-the-Middle Problem?

The lost-in-the-middle problem describes a tendency observed in some language models to use information at the beginning or end of a long context more effectively than information placed in the middle. The effect depends on the model, task, and context length; it does not happen identically in every situation.

For example, a context might contain:

- **Beginning:** Python is a programming language.
- **Middle:** Machine learning allows computers to learn patterns from data.
- **End:** London is the capital of the United Kingdom.

If the question is “How do computers learn patterns from data?”, the relevant information is in the middle. A model may not always use that information as effectively as expected.

## Why It Matters in RAG

A RAG system retrieves documents and places them into a context for the LLM. Even when the retriever finds useful information, the model may not use every part of a long context equally well.

The lesson is that retrieving the correct information is not enough; how the information is arranged can also matter.

## Today's Technique: Context Re-ordering

Context re-ordering changes the order of selected documents before they are passed to the LLM. One strategy to experiment with is placing highly relevant documents near the beginning and end, with other documents between them.

Example relevance scores:

| Document | Relevance score |
|---|---:|
| Document A | 0.95 |
| Document B | 0.60 |
| Document C | 0.90 |
| Document D | 0.50 |
| Document E | 0.85 |

An experimental ordering could place Document A first and Document C last, with the other documents between them.

This strategy is not guaranteed to improve every model or task. Test it rather than assuming it works.

## Suggested Workflow

1. Retrieve relevant documents for a question.
2. Rank the documents by relevance.
3. Keep the selected documents.
4. Arrange a strong result near the beginning and another strong result near the end.
5. Place the remaining results between them.
6. Compare the output with the original ordering using the same question and documents.

Today's experiment is about changing order, not removing useful documents.

## Reranking vs. Context Re-ordering

- **Reranking** changes the ranking of documents based on their relevance to the question.
- **Context re-ordering** arranges selected documents for presentation to the LLM.

They are related, but not identical. A context-ordering strategy can use relevance scores from an earlier reranking step.

## Where It Fits in the RAG Pipeline

```text
User Question
      ↓
Query Processing
      ↓
Retrieval
      ↓
Reranking
      ↓
Context Compression
      ↓
Context Re-ordering
      ↓
Prompt Construction
      ↓
LLM
      ↓
Answer
```

Each step has a different purpose:

- **Retrieval:** Find relevant information.
- **Reranking:** Improve the ranking of retrieved results.
- **Context compression:** Remove unnecessary information while preserving useful details.
- **Context re-ordering:** Arrange retained information before sending it to the LLM.

## Today's Comparison Experiment

Compare two versions using the same question and documents.

### Experiment A — Original order

```text
Document A
Document B
Document C
Document D
Document E
```

### Experiment B — Re-ordered context

```text
Document A  ← strong result
Document B
Document D
Document E
Document C  ← strong result
```

Check:

- Did the answer use the correct information?
- Did the answer become more accurate or complete?
- Did the model overlook any relevant details?
- Did the new ordering make a measurable difference?

With a small dataset, the result may be inconclusive. That is still useful: the goal is to test the technique rather than assume it works.
