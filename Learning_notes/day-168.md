# 2. What Is Fine-Tune Evaluation?

Fine-tune evaluation is the process of measuring how well a model performs after additional training.

Fine-tuning changes a model's behaviour by training it on task-specific examples.

However, training does not guarantee improvement.

A fine-tuned model might:
- Follow instructions better.
- Produce more relevant answers.
- Learn a particular response format.
- Memorise training examples.
- Generate incorrect information.
- Perform worse on tasks it previously handled well.

Therefore, we need a systematic evaluation process.

**Main objective: Determine whether the fine-tuned model performs better than the original model on the intended task without introducing unacceptable regressions.**

# 3. Base Model vs Fine-Tuned Model

A base model is the original pretrained model before our additional fine-tuning.

A fine-tuned model is the same model after additional task-specific training.

We compare both models using the same evaluation dataset.

### Example

Imagine we fine-tune a language model to improve its ability to answer technical questions.

We test both models using 100 unseen questions.

| Evaluation Criteria | Base Model | Fine-Tuned Model |
|---|---:|---:|
| Instruction Following | 3.0 | 4.5 |
| Accuracy | 3.5 | 4.2 |
| Relevance | 3.2 | 4.6 |
| Clarity | 4.0 | 4.4 |
| Completeness | 3.1 | 4.3 |

These are hypothetical scores.

The results suggest that fine-tuning improved the measured performance.

However, we must use actual test results before claiming that our model has improved.

# 4. Important Evaluation Metrics

Different tasks require different evaluation metrics.

## 4.1 Accuracy

Accuracy measures the percentage of correct predictions.

Formula:

Accuracy = Correct Predictions / Total Predictions

Example:

If a model answers 90 out of 100 questions correctly:

Accuracy = 90 / 100 = 90%

Useful for classification and tasks with clearly defined correct answers.

## 4.2 Precision

Precision measures how many predicted positive cases were actually positive.

Formula:

Precision = TP / (TP + FP)

Where:
- TP = True Positives
- FP = False Positives

## 4.3 Recall

Recall measures how many actual positive cases were correctly identified.

Formula:

Recall = TP / (TP + FN)

Where:
- TP = True Positives
- FN = False Negatives

## 4.4 F1 Score

F1 combines precision and recall.

Formula:

F1 = 2 × (Precision × Recall) / (Precision + Recall)

Useful when evaluating classification tasks, especially when class distributions are imbalanced.

## 4.5 Exact Match

Exact Match measures whether the generated answer exactly matches the expected answer.

Example:

Expected: London

Generated: London

Result: Match.

Expected: London

Generated: The capital of the UK is London.

Result: No exact match.

Exact Match is useful for tasks where an exact answer is expected, but it can be too strict for natural language responses.

## 4.6 ROUGE

ROUGE measures overlap between generated text and reference text.

It is commonly used for summarisation tasks.

## 4.7 BLEU

BLEU measures n-gram overlap between generated text and reference text.

It is commonly used in machine translation.

**Important:** High text overlap does not necessarily mean an answer is factually correct or useful.

# 5. LLM-Specific Evaluation

Traditional metrics are not always sufficient for evaluating language models.

For open-ended responses, we may need to evaluate several dimensions.

| Criterion | Description |
|---|---|
| Accuracy | Is the information correct? |
| Relevance | Does the answer address the question? |
| Instruction Following | Does it follow the requested instructions? |
| Clarity | Is the answer understandable? |
| Completeness | Does it cover the necessary information? |
| Consistency | Does it behave reliably across similar questions? |
| Safety | Does it avoid harmful or inappropriate outputs? |

We can use human evaluation or an automated evaluation process.

### Human Evaluation

A human reviewer examines generated responses and assigns scores using a predefined rubric.

Advantages:
- Can judge meaning and usefulness.
- Can identify subtle mistakes.
- Can evaluate different acceptable answers.

Limitations:
- Takes time.
- Can involve subjective judgement.
- Requires consistent scoring guidelines.

### LLM-as-a-Judge

An LLM evaluates another model's responses using predefined criteria.

For example, an evaluator model can score an answer from 1 to 5 based on accuracy and relevance.

Advantages:
- Can evaluate many responses quickly.
- Can apply consistent evaluation instructions.
- Reduces manual workload.

Limitations:
- The evaluator can make mistakes.
- Scores may be biased.
- Different evaluator models can produce different judgements.

For important evaluations, use human review to validate automated scores.

# 6. Overfitting in Fine-Tuning

Overfitting happens when a model learns the training examples too closely and performs poorly on unseen examples.

### Example

Training question:

"What is Python?"

Training answer:

"Python is a programming language."

If the model memorises the exact training examples but cannot answer different questions about Python, it may be overfitting.

### Signs of Overfitting

- Training performance improves.
- Validation performance stops improving.
- Validation performance becomes worse.
- The model struggles with unseen examples.
- The model reproduces memorised training responses.

### How to Reduce Overfitting

1. Use a representative dataset.
2. Remove duplicate examples.
3. Use a separate validation dataset.
4. Monitor validation performance.
5. Adjust the number of training epochs.
6. Use appropriate regularisation.
7. Evaluate using unseen test examples.

---

# 7. Catastrophic Forgetting

Catastrophic forgetting occurs when a model loses some previously learned capabilities while learning a new task.

### Example

A pretrained model can:
- Answer general questions.
- Explain programming concepts.
- Summarise documents.

After fine-tuning on a very narrow dataset, it might become better at that specific task but worse at general questions.

This is why we should evaluate both:

1. Task-specific performance.
2. General capabilities that we want to preserve.

A fine-tuned model should not be considered successful merely because it improves one narrow metric.

# 8. Build a Reliable Evaluation Dataset

A good evaluation dataset should be:

- Separate from the training dataset.
- Representative of real-world questions.
- Diverse enough to test different situations.
- Free from unnecessary duplicates.
- Consistent in structure.
- Large enough to provide meaningful evidence.

### Example Dataset

```json
{"instruction": "Explain machine learning in simple terms.", "input": "", "expected_output": "Machine learning allows computers to learn patterns from data."}
{"instruction": "What is Python?", "input": "", "expected_output": "Python is a programming language used for software development, automation and data science."}
{"instruction": "Explain what an API does.", "input": "", "expected_output": "An API allows different software applications to communicate."}
```

Each line is an independent JSON object.

The examples above are illustrative. A real evaluation dataset should contain enough diverse examples to represent the intended task.

# 9. Evaluation Pipeline

A reproducible evaluation process follows a sequence.

```text
          Evaluation Dataset
                  |
                  v
          Load Base Model
                  |
                  v
       Generate Base Responses
                  |
                  v
        Load Fine-Tuned Model
                  |
                  v
     Generate Fine-Tuned Responses
                  |
                  v
         Apply Evaluation Metrics
                  |
                  v
          Compare Both Models
                  |
                  v
           Record Results
                  |
                  v
          Analyse Performance
```

Both models must receive the same prompts and use the same generation settings wherever possible.

For fair comparison, keep constant:
- Evaluation examples.
- Prompt templates.
- Generation parameters.
- Evaluation criteria.
- Scoring methodology.

# 12. Reproducibility

Reproducibility means being able to repeat an experiment and understand how its results were produced.

A good evaluation document should record:

| Item | Information |
|---|---|
| Base Model | Original model name and version |
| Fine-Tuned Model | Model name and adapter version |
| Dataset | Evaluation dataset location |
| Dataset Version | Dataset revision |
| Prompt Template | Prompt format |
| Temperature | Generation temperature |
| Maximum Tokens | Maximum generated tokens |
| Evaluation Metrics | Metrics used |
| Evaluation Date | Date of experiment |
| Results | Actual measured scores |

Without these details, comparing results across experiments becomes difficult.
