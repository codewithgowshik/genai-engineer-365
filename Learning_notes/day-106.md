# Day 106 — Add Caching for Embeddings

## Objective

Learn how to polish a Streamlit application and add caching for the embedding model.

Today focuses on improving application performance by avoiding unnecessary repeated loading of an expensive resource.

---

## 1. What is Caching?

Caching means storing something that is expensive to create or calculate so it can be reused later instead of doing the same work again.

```text
Without caching:

Request 1 → create/load → result
Request 2 → create/load → result
Request 3 → create/load → result
```

With caching:

```text
Request 1 → create/load → store
Request 2 → reuse stored resource
Request 3 → reuse stored resource
```

The main goal is to avoid unnecessary repeated work.

---

## 2. Why Does Streamlit Need Caching?

Streamlit can rerun the Python script when the user interacts with the application.

```text
User enters query
      ↓
User clicks Search
      ↓
Streamlit reruns the script
      ↓
Python code runs again
```

If an embedding model is loaded every time the script runs, the application may perform unnecessary work.

Our project uses:

```python
SentenceTransformer("all-MiniLM-L6-v2")
```

for creating embeddings.

The model is a resource that we want to reuse.

---

## 3. `st.cache_resource`

Streamlit provides:

```python
@st.cache_resource
```

for caching resources such as models.

Example:

```python
import streamlit as st
from sentence_transformers import SentenceTransformer


@st.cache_resource
def load_model():

    return SentenceTransformer(
        "all-MiniLM-L6-v2"
    )


model = load_model()
```

The first time `load_model()` runs, the model is loaded.

After that, Streamlit can reuse the cached model during reruns.

---

## 4. Understanding the Flow

Without caching:

```text
Streamlit rerun
      ↓
Load embedding model
      ↓
Run application
```

With caching:

```text
First run
   ↓
Load model
   ↓
Store in cache
   ↓
Later rerun
   ↓
Reuse model
```

This can make the application more efficient.

---

## 5. Why Cache the Model?

The embedding model is relatively expensive compared with ordinary Python operations.

Loading it repeatedly is unnecessary if the same model can be reused.

Caching allows the application to keep the resource available for later reruns.

---

## 6. Basic Streamlit Example

```python
import streamlit as st
from sentence_transformers import SentenceTransformer


st.title("Semantic Search Engine")


@st.cache_resource
def load_model():

    return SentenceTransformer(
        "all-MiniLM-L6-v2"
    )


model = load_model()


query = st.text_input(
    "Enter your search query"
)


if st.button("Search"):

    st.write("Searching...")
```

The important part is:

```python
@st.cache_resource
def load_model():
```

This tells Streamlit to cache the resource returned by the function.

## 8. Important Implementation Detail

The existing search backend already loads the embedding model.

Therefore, simply creating another cached model in `app.py` does not automatically make the backend use that cached model.

A clean implementation should eventually use one reusable model-loading path shared by the application and search code.

For today's learning goal, remember:

```text
Expensive resource
      ↓
Cache it
      ↓
Reuse it
```

Avoid unnecessarily loading duplicate models.
