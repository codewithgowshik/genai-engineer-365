# Day 130 — Context Compression

## Objective

Learn what context compression is and add a simple compression step to a RAG pipeline.

## What Is Context Compression?

Context compression reduces retrieved information to the parts most useful for answering the user's question.

A retriever may return several documents, but not every sentence will help answer the question. Context compression tries to remove unnecessary information while preserving the details needed to answer correctly.

The goal is not simply to make context shorter. It is to make the context more focused without losing important facts.

## Simple Example

Question:

> What is semantic search?

Retrieved text:

> Semantic search finds information based on meaning rather than relying only on exact keywords. It uses embeddings to represent text as numerical vectors. These vectors help a system identify documents with similar meanings. Python is a programming language used to build software applications.

The last sentence about Python does not help answer the question.

A compressed context could be:

> Semantic search finds information based on meaning rather than relying only on exact keywords. It uses embeddings to represent text as numerical vectors and identify documents with similar meanings.

The compressed context is shorter but preserves the relevant information.

## Two Approaches

### 1. Extractive Compression

Select relevant sentences directly from the original documents.

- Keeps the original wording.
- Can be easier to implement and inspect.
- Avoids generating new wording, although the selected text can still be incomplete or misleading without its surrounding context.

Flow:

Original documents → Select relevant sentences → Compressed context

### 2. Abstractive Compression

Use an LLM to summarise the relevant information in fewer words.

- Can produce a shorter, more natural summary.
- Changes the original wording.
- Must be checked carefully so it does not add unsupported facts or remove important details.

Flow:

Original documents → LLM summarisation → Shorter summary

For an initial experiment, extractive compression is a straightforward place to start.

## Where It Fits in RAG

A RAG pipeline with context compression can look like this:

User Question  
↓  
Query Processing  
↓  
Retrieval  
↓  
Reranking  
↓  
Context Compression  
↓  
Prompt Construction  
↓  
LLM  
↓  
Grounded Answer

Each component has a different job:

- **Retrieval:** Find potentially relevant documents.
- **Reranking:** Improve the order of retrieved documents.
- **Context compression:** Keep the information useful for the question.
- **LLM:** Generate an answer using the supplied context.

Reranking changes the order of results. Compression changes which information is retained.

## How to Evaluate It

Check three things:

1. **Relevance:** Was unnecessary information removed?
2. **Completeness:** Was the information needed to answer preserved?
3. **Grounding:** Does the compressed context still support the answer?

A shorter context is not automatically better. If compression removes an important fact, the final RAG answer may become worse.

## What I Learned Today

- Retrieved documents can contain irrelevant details.
- Context compression tries to preserve useful information while removing unnecessary text.
- Extractive compression selects original sentences.
- Abstractive compression uses a model to summarise information in new wording.
- Compression happens after retrieval and can be placed after reranking.
- The compressed context must still contain enough evidence to answer the question correctly.
