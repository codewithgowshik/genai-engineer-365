## 1. Introduction

When building an AI application, we need to decide how to make an AI model produce the answers we want.

There are three common approaches:

1. Prompt Engineering
2. Retrieval-Augmented Generation (RAG)
3. Fine-Tuning

Each approach solves a different problem.

The important thing is knowing **when to use each one**.

---

## 2. What Is Prompt Engineering?

Prompt engineering means giving an AI model clear instructions to guide its response.

We do not change the model itself. We simply improve the instructions we give it.

### Example

**Basic prompt:**

```text
Explain artificial intelligence.
```

**Improved prompt:**

```text
You are an AI teacher.

Explain artificial intelligence to a beginner.
Use simple English.
Give three real-world examples.
Keep your answer under 150 words.
```

The second prompt gives the model more direction.

### When should we use prompt engineering?

- When we want a specific response format.
- When we need a particular tone or style.
- When we want the model to follow specific instructions.
- When we are building a basic AI application.

**Remember:** Prompt engineering changes the instructions, not the model's parameters.

---

## 3. What Is RAG?

RAG stands for **Retrieval-Augmented Generation**.

It allows an AI model to retrieve relevant information from an external knowledge source before generating an answer.

This is useful when the model needs information that is not included in its original training data.

### Real-world example

Imagine we build an AI chatbot for a university.

Students ask questions such as:

- What is the attendance requirement?
- What is the assignment submission deadline?
- What are the university's examination rules?

Instead of relying only on the model's existing knowledge, we connect it to university documents.

The AI retrieves relevant information from those documents and uses it to answer.

### How does RAG work?

```text
University Documents
        |
        v
Document Processing
        |
        v
Text Chunking
        |
        v
Create Embeddings
        |
        v
Store in Vector Database
        |
        v
Student Asks a Question
        |
        v
Retrieve Relevant Information
        |
        v
Send Information to LLM
        |
        v
Generate Answer
```

### Important RAG components

**1. Document Processing**

Collect information from PDFs, text files, websites, and other sources.

**2. Chunking**

Break large documents into smaller pieces so relevant information can be retrieved more easily.

**3. Embeddings**

Convert text into numerical representations that capture semantic meaning.

**4. Vector Database**

Store embeddings and associated text so relevant information can be searched.

Examples:

- Chroma
- Pinecone
- Weaviate

**5. Retrieval**

Find the most relevant information based on the user's question.

**6. Generation**

Pass the retrieved information to the LLM so it can generate an answer.

### When should we use RAG?

- When an AI needs company documents.
- When information changes frequently.
- When building customer-support chatbots.
- When answering questions from PDFs or databases.
- When working with private or specialised knowledge.

**Remember:** RAG gives the model access to relevant information. It does not train the model.

---

## 4. What Is Fine-Tuning?

Fine-tuning means taking an existing pretrained model and training it further using a carefully prepared dataset.

This helps the model learn a particular behaviour, style, or task pattern.

Unlike prompt engineering and RAG, fine-tuning updates the model's trainable parameters.

### Real-world example

Imagine we are building an AI customer-support assistant.

We want it to:

- Follow our company's communication style.
- Respond consistently.
- Classify customer complaints.
- Produce answers in a specific format.

We can prepare a dataset containing examples of good customer-support conversations and use it to fine-tune a model.

The model can then become better suited to those tasks.

### What is LoRA?

LoRA stands for **Low-Rank Adaptation**.

It is a parameter-efficient fine-tuning technique.

Instead of updating all the original model parameters, LoRA introduces smaller trainable components that adapt the model.

This can reduce the memory and computational resources required for fine-tuning.

### When should we use fine-tuning?

- When we need consistent output patterns.
- When a model needs to learn a specialised task.
- When prompt engineering is not producing reliable behaviour.
- When we need a particular response style across many requests.

**Remember:** Fine-tuning changes the model's learned behaviour by updating trainable parameters.

---

## 5. Main Differences

| Feature | Prompt Engineering | RAG | Fine-Tuning |
|---|---|---|---|
| Main purpose | Guide the model | Provide external knowledge | Adapt model behaviour |
| Changes model parameters? | No | No | Yes |
| Uses external documents? | Not necessarily | Yes | Not required |
| Requires training? | No | No | Yes |
| Best for | Instructions and formatting | Knowledge-based answers | Specialised behaviour |
| Complexity | Low | Medium | High |

## 6. Real-World Comparison

Imagine we are developing an AI assistant for a hospital.

### Scenario 1: Prompt Engineering

We want the assistant to explain medical terminology in simple language.

We give it clear instructions about how to respond.

**Solution:** Prompt Engineering.

### Scenario 2: RAG

We want the assistant to answer questions using the hospital's latest policies and approved documents.

We connect it to those documents.

**Solution:** RAG.

### Scenario 3: Fine-Tuning

We want the assistant to consistently classify incoming support requests into predefined categories using a particular output format.

We prepare examples and fine-tune the model for that task.

**Solution:** Fine-Tuning.

*Note: These are technical examples, not a recommendation to use an AI model as a replacement for qualified medical professionals.*

---

## 7. When Should We Choose Each Approach?

Use this simple decision-making guide.

| Your requirement | Recommended approach |
|---|---|
| I want to control the AI's response format | Prompt Engineering |
| I want the AI to answer using my PDFs | RAG |
| I want the AI to access updated company information | RAG |
| I want the AI to follow a specialised response style consistently | Fine-Tuning |
| I want to give the AI simple instructions | Prompt Engineering |
| I want the AI to learn a specialised task pattern | Fine-Tuning |

### Important recommendation

Do not immediately start fine-tuning a model.

Follow this order:

1. Start with prompt engineering.
2. If the model needs external knowledge, implement RAG.
3. If the model still struggles with consistent specialised behaviour, evaluate fine-tuning.

This avoids unnecessary training costs and complexity.

---

## 8. Can We Combine All Three?

Yes!

In real-world AI applications, we can combine prompt engineering, RAG, and fine-tuning.

### Example: AI University Assistant

**Prompt Engineering:**

Give the AI instructions to answer students politely and clearly.

**RAG:**

Connect the AI to university documents, policies, and course information.

**Fine-Tuning:**

Fine-tune the model if we need more consistent specialised behaviour that prompting alone cannot reliably achieve.

### Combined Architecture

```text
             User Question
                   |
                   v
            Prompt Instructions
                   |
                   v
            RAG Retrieval
                   |
                   v
          Relevant Documents
                   |
                   v
           Fine-Tuned LLM
                   |
                   v
             Final Answer
```

The exact architecture can vary depending on the application.

## 9. Key Terminology

| Term | Meaning |
|---|---|
| Prompt | Instructions given to an AI model |
| Prompt Engineering | Improving prompts to guide model responses |
| RAG | Retrieval-Augmented Generation |
| Embeddings | Numerical representations of text |
| Chunking | Splitting documents into smaller sections |
| Vector Database | Database designed to store and search vector embeddings |
| Fine-Tuning | Additional training of a pretrained model |
| LoRA | Parameter-efficient fine-tuning technique |
| LLM | Large Language Model |
| Parameters | Numerical values learned by a model during training |

---

## 10. Important Things to Remember

1. Prompt Engineering tells the AI what to do.
2. RAG gives the AI relevant information.
3. Fine-Tuning trains the AI to perform a task or behave differently.
4. RAG does not update the model's parameters.
5. Prompt Engineering does not require model training.
6. Fine-Tuning requires a suitable dataset and computational resources.
7. Fine-Tuning is not the best solution for frequently changing information.
8. We should try prompting first before considering more complex approaches.
9. We can combine all three approaches in one application.

### My Final Understanding

Prompt Engineering, RAG, and Fine-Tuning are three different ways to improve an AI application.

We should choose the approach based on the problem we are solving rather than automatically using the most complex technique.

**Start simple with prompts, introduce RAG when external knowledge is required, and consider fine-tuning when specialised behaviour needs additional training.**
