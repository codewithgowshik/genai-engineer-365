## 1. What is RAG?

**RAG** stands for **Retrieval-Augmented Generation**. It combines two processes:

1. **Retrieval:** Find relevant information from a document collection.
2. **Generation:** Give the retrieved information to a language model (LLM) so it can generate an answer grounded in that context.

### Example

Question: `What is semantic search?`

A RAG system searches its document collection for relevant information about semantic search, then passes that information to an LLM to help generate an answer.

RAG allows an application to use information retrieved from its own documents instead of relying only on the model's existing knowledge.

## 3. Typical RAG Data Flow

### Ingestion flow

```text
Source documents
      ↓
Read documents
      ↓
Create embeddings
      ↓
Store documents and embeddings in ChromaDB
```

### Query-time flow

```text
User question
      ↓
(Optional) Generate alternative queries
      ↓
Retrieve candidate documents from ChromaDB
      ↓
(Optional) Combine ranked results with RRF
      ↓
(Optional) Rerank, compress, or reorder context
      ↓
Pass question + selected context to the LLM
      ↓
Generate an answer
```

The optional stages should only be described as active if they are actually connected in the current code.

## 4. RAG Design Patterns

A **design pattern** is a reusable approach to a recurring engineering problem.

| Pattern | What it does | Why it can help |
|---|---|---|
| Basic RAG | Retrieves documents and passes them to an LLM | Provides a simple baseline pipeline |
| Multi-query retrieval | Generates several alternative search queries | Searches for relevant information from different angles |
| Hybrid search | Combines keyword and semantic search | Can help with both exact terms and conceptual matches |
| Reranking | Reorders candidate documents by relevance | Can place the most useful documents nearer the top |
| Context compression | Removes unnecessary context while retaining important information | Can reduce prompt size and irrelevant content |
| Reciprocal Rank Fusion (RRF) | Combines ranked lists using their rank positions | Can combine results without requiring scores from different retrievers to be directly comparable |
| Context reordering | Changes the position of retrieved documents | Lets you experiment with how context order affects answer quality |

You do not need to implement every pattern today. The task is to document what exists and clearly distinguish working components from experiments or future improvements.

5. **Generation:** How is retrieved context passed to the LLM?
6. **Limitations:** What can cause poor retrieval or incorrect answers?
7. **Future improvements:** What would you test or add next?

### Example problem and solution

**Problem:** An LLM may not have access to specific information contained in a custom document collection.

**Solution:** Retrieve relevant documents from a searchable collection and use them as context when generating an answer.

**Limitation:** If retrieval returns irrelevant or incomplete information, the generated answer may also be incomplete or incorrect. RAG does not automatically guarantee factual answers.

## 8. Key Takeaways

- RAG combines retrieval with LLM generation.
- Ingestion prepares and stores searchable document representations.
- Retrieval quality strongly affects the context available to the LLM.
- Multi-query retrieval, hybrid search, reranking, RRF, compression, and reordering are different techniques—not necessarily all active in one pipeline.
- Architecture documentation should describe the code that exists, not only the system you intend to build.
