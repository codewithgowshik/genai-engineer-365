## Today's Goal

Create a small, trustworthy set of questions and expected answers that can be reused to evaluate the RAG system.

## 1. Why Evaluate RAG?

A RAG system can produce fluent answers that are incomplete, incorrect, or unsupported by the retrieved context. Evaluation helps us test the system instead of assuming it works.

For each question, consider:

- **Retrieval quality:** Did the system retrieve the right documents?
- **Answer correctness:** Is the generated answer factually correct?
- **Groundedness:** Is the answer supported by the retrieved context?

## 2. What Is an Evaluation Dataset?

An evaluation dataset is a collection of questions and their expected answers. The expected answers act as references when checking system output.

**Important:** Expected answers should be supported by the actual documents in `data/documents.txt`. Otherwise, a useful answer might be incorrectly marked as wrong.

## 3. Create the Evaluation File

Add `eval_set.json` inside the existing `data/` directory:

```text
retrieval-argument-generation/
├── data/
│   ├── documents.txt
│   └── eval_set.json
```

Example starter dataset:

```json
[
  {
    "question": "What is Python?",
    "expected_answer": "Python is a programming language."
  },
  {
    "question": "What is semantic search?",
    "expected_answer": "Semantic search finds information based on meaning."
  },
  {
    "question": "What is a vector database?",
    "expected_answer": "A vector database stores and searches vector embeddings."
  }
]
```

These are starter examples. Check that each expected answer is supported by the project's own documents before using it for evaluation.

## 4. Today's Build Task

1. Read `data/documents.txt`.
2. Choose facts and topics that are actually covered by the documents.
3. Write approximately **10–20 question-and-answer pairs** in `data/eval_set.json`.
4. Use valid JSON syntax: double quotes around keys and string values, commas between fields/items, and no trailing commas.
5. Check every expected answer against the source documents.

You do not need to build an automated evaluation framework today. First, create a reliable dataset that can be reused in later experiments.

## 5. How the Dataset Helps

The same questions can be used to compare changes to the RAG pipeline, for example:

- Basic retrieval versus multi-query retrieval.
- Retrieval before and after reranking.
- Different values of `k` (the number of retrieved results).
- Answer correctness and groundedness.
- Changes to retrieval settings over time.

Using the same evaluation questions makes comparisons more consistent.

## Key Terms

- **Evaluation dataset:** Reusable examples used to test a system.
- **Expected answer:** Reference answer used when reviewing generated output.
- **Retrieval quality:** How well the system finds relevant source material.
- **Answer correctness:** Whether an answer is factually correct.
- **Groundedness:** Whether the answer is supported by the retrieved context.
- **Benchmark:** A consistent set of tests used to compare system behaviour.
