# Day 135 — Measure Retrieval Recall

**Week:** 20 — RAG Evaluation  
**Phase:** 4 — Retrieval-Augmented Generation (RAG)  
**Learn:** Retrieval metrics (Recall and MRR)  
**Build:** Measure retrieval recall

## 1. Why evaluate retrieval?

A RAG system can only use the information it retrieves. If retrieval returns irrelevant documents or misses useful information, the generated answer may be incomplete or incorrect. Retrieval metrics help measure how well search finds relevant documents.

## 2. Retrieval Recall

**Recall measures the proportion of all relevant documents that the system successfully retrieves.**

**Recall = relevant documents retrieved / total relevant documents**

Example: There are 4 relevant documents for a question. The system retrieves 2 of them.

**Example:** Recall = 2 / 4 = 0.5 = 50%

- **1.0 (100%)**: all known relevant documents were retrieved.
- **0.5 (50%)**: half were retrieved.
- **0.0 (0%)**: none were retrieved.

Recall depends on having a reliable list of relevant documents for each question.

## 3. Mean Reciprocal Rank (MRR)

**MRR measures how highly the first relevant result appears in the ranked search results, averaged across multiple questions.**

First calculate the reciprocal rank for each question:

**Reciprocal Rank (RR) = 1 / rank of the first relevant result**

If the first relevant result is at rank 3:

**Example:** RR = 1 / 3 = approximately 0.333

If the first result is relevant, the reciprocal rank is 1.

Then average the reciprocal ranks:

**MRR = (RR for question 1 + RR for question 2 + ... + RR for question n) / number of questions**

Example: Reciprocal ranks are 1.0, 0.5, and 0.333.

**Example:** MRR = (1.0 + 0.5 + 0.333) / 3 = approximately 0.611

Higher MRR means the first relevant result tends to appear nearer the top.

## 4. Recall vs. MRR

| Metric | What it measures | Main question |
|---|---|---|
| Recall | Coverage of relevant documents | Did the system retrieve the relevant information? |
| MRR | Position of the first relevant result | How high was the first relevant result ranked? |

A system can retrieve many relevant documents (high recall) but still rank them poorly (low MRR).

## 5. Today's build

Use the evaluation dataset created on Day 134 to test retrieval. For each question:

1. Load the question from the evaluation set.
2. Run it through the retrieval function.
3. Compare the retrieved documents with the known relevant documents.
4. Calculate recall for that question.
5. Average the per-question recall values to obtain the dataset's average recall.

For MRR, find the rank of the first relevant result for each question, calculate its reciprocal rank, and average those values.

Adapt the structure to your existing `data/eval_set.json`; do not replace your existing data without checking it first.

These are illustrative examples. The relevant-document references must match content in your actual corpus and the way your retrieval function returns documents. A reference answer is not automatically the same thing as a reference document; make sure your evaluation compares like with like.

## 6. Key points

- Recall measures how many known relevant documents were retrieved.
- MRR measures the rank of the first relevant result.
- Both metrics require relevance labels for evaluation questions.
- Use the same evaluation set when comparing retrieval methods so the comparison is consistent.
- A metric is only as trustworthy as the relevance labels and evaluation setup behind it.
