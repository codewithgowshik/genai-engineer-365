# Day 128 — Cross-Encoder Rerankers

## Objective

Learn why cross-encoder rerankers can improve retrieval quality and compare retrieval results with and without reranking.

## What Is Reranking?

Reranking is a second step after the first retrieval stage.

The first retriever quickly finds candidate documents. The reranker then looks at those candidates and changes their order based on relevance.

Simple flow:

Question → Retrieval → Candidate Documents → Reranking → Best Documents

The main idea is:

> Retrieve broadly first, then rank the candidates more carefully.

## What Is a Cross-Encoder?

A cross-encoder looks at the question and a candidate document together.

Instead of creating separate representations and comparing them:

Question → Vector
Document → Vector
→ Similarity

A cross-encoder does:

Question + Document → Cross-Encoder → Relevance Score

For example:

Question:
How do computers learn from data?

Document:
Machine learning allows computers to learn patterns from data.

The cross-encoder gives the pair a relevance score. Higher relevance means the document is a better match for the question.

## Why Does Reranking Help?

Vector retrieval is designed to be fast. It can quickly find a group of potentially useful documents, but the order is not always perfect.

For example:

1. Artificial intelligence enables computer systems...
2. Deep learning uses neural networks...
3. Machine learning allows computers to learn patterns from data.

The third result may actually be the strongest answer.

A reranker can examine the candidates again and move the most relevant document higher.

## Two-Stage Retrieval

A practical retrieval system can use two stages.

### Stage 1 — Retrieval

Find a larger set of candidates quickly.

Question → Embedding → Vector Database → Top candidates

### Stage 2 — Reranking

Score those candidates more carefully.

Top candidates → Cross-Encoder → Relevance Scores → New Ranking

This gives us:

> Retriever = fast and broad

> Reranker = slower but more precise

## Why Not Rerank the Entire Database?

Suppose the database contains 100,000 documents.

Running a cross-encoder against every document would be expensive and slow.

Instead:

100,000 documents
↓
Fast retrieval
↓
20 candidates
↓
Cross-encoder
↓
Best 5

The first stage reduces the number of documents that need detailed scoring.

## What I Learned Today

- A reranker is a second ranking step after retrieval.
- A cross-encoder evaluates the question and candidate document together.
- Cross-encoders can provide more precise relevance scoring.
- Retrieval should first find candidates quickly.
- Reranking can then improve the order of those candidates.
- Reranking the entire database would be inefficient, so it is normally applied to a smaller candidate set.
- Comparing results with and without reranking helps evaluate whether reranking actually improves retrieval quality.
