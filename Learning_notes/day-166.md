# 1. What Is LoRA?

LoRA stands for **Low-Rank Adaptation**.

It is a Parameter-Efficient Fine-Tuning (PEFT) technique used to adapt pretrained language models without updating all their original parameters.

Normally, full fine-tuning updates the model's original weights.

LoRA takes a different approach:

- Keeps the original pretrained weights frozen.
- Introduces smaller trainable matrices.
- Trains those additional parameters.
- Uses the learned updates to adapt the model.

The main objective is to reduce the computational and memory requirements of fine-tuning.

## Full Fine-Tuning vs LoRA

| Full Fine-Tuning | LoRA |
|---|---|
| Updates original model weights | Keeps original weights frozen |
| Updates most or all model parameters | Trains additional LoRA parameters |
| Higher memory requirements | Often lower memory requirements |
| Can produce large checkpoints | Can produce smaller adapter checkpoints |

# 2. How Does LoRA Work Internally?

A neural network contains weight matrices.

Consider an original weight matrix:

`W`

During normal fine-tuning, the model updates this matrix.

LoRA introduces two smaller matrices:

- Matrix A
- Matrix B

The adapted weight can be represented as:

`W' = W + (B × A) × (alpha / r)`

Where:

| Symbol | Meaning |
|---|---|
| W | Original pretrained weights |
| A | First trainable low-rank matrix |
| B | Second trainable low-rank matrix |
| r | LoRA rank |
| alpha | LoRA scaling parameter |
| W' | Adapted weights |

The original matrix remains frozen while the additional matrices learn the required adaptation.

## Example

Imagine the original weight matrix has dimensions:

`4096 × 4096`

Original parameters:

`4096 × 4096 = 16,777,216`

Suppose LoRA rank is 8.

Matrix A:

`8 × 4096 = 32,768`

Matrix B:

`4096 × 8 = 32,768`

Total LoRA parameters:

`32,768 + 32,768 = 65,536`

This is considerably smaller than the original matrix.

**Important:** This is an illustrative example for one matrix, not the parameter count of an entire language model.

# 3. Important LoRA Hyperparameters

LoRA configuration requires several important hyperparameters.

## A. Rank (r)

Rank controls the dimensions of the low-rank matrices.

Example:

```python
r = 8
```

Common experimental values:

- 4
- 8
- 16
- 32
- 64

Higher rank generally increases adaptation capacity but also increases the number of trainable parameters.

## B. LoRA Alpha

Alpha controls the scaling of the LoRA update.

Example:

```python
lora_alpha = 16
```

The scaling factor is commonly:

`alpha / r`

If:

- Alpha = 16
- Rank = 8

Then:

`16 / 8 = 2`

## C. LoRA Dropout

Dropout helps reduce overfitting.

Example:

```python
lora_dropout = 0.05
```

This represents a dropout probability of 5%.

## D. Target Modules

Target modules specify which model layers receive LoRA adapters.

Example:

```python
target_modules = [
    "q_proj",
    "k_proj",
    "v_proj",
    "o_proj"
]
```

These are commonly associated with transformer attention projections.

Some architectures also support LoRA on MLP projection layers.

The correct module names depend on the model architecture.

## E. Bias

Example:

```python
bias = "none"
```

This means LoRA does not train the bias parameters.

## F. Task Type

Example:

```python
task_type = "CAUSAL_LM"
```

This configures PEFT for causal language modelling, commonly used for text-generation models.

# 4. LoRA vs Instruction Tuning vs PEFT

These concepts are related but different.

| Concept | Meaning |
|---|---|
| Instruction Tuning | Teaching a model to follow instructions |
| SFT | Supervised training using input-output examples |
| PEFT | Family of parameter-efficient fine-tuning methods |
| LoRA | A specific PEFT technique |

Remember:

- Instruction tuning describes what we want the model to learn.
- SFT describes a supervised training approach.
- PEFT describes how we can adapt a model efficiently.
- LoRA is one technique within PEFT.

LoRA can be used during supervised instruction tuning.

# 8. Configure the LoRA Run

Create `configure_lora.py`.

```python
import os
import json

from peft import LoraConfig, TaskType
from transformers import TrainingArguments


# MODEL CONFIGURATION

MODEL_NAME = "Qwen/Qwen2.5-0.5B"

OUTPUT_DIR = "./lora-output"


# LORA CONFIGURATION

lora_config = LoraConfig(

    r=8,

    lora_alpha=16,

    lora_dropout=0.05,

    target_modules=[
        "q_proj",
        "k_proj",
        "v_proj",
        "o_proj",
        "gate_proj",
        "up_proj",
        "down_proj"
    ],

    bias="none",

    task_type=TaskType.CAUSAL_LM
)


# TRAINING CONFIGURATION

training_settings = {

    "output_dir": OUTPUT_DIR,

    "per_device_train_batch_size": 1,

    "gradient_accumulation_steps": 4,

    "learning_rate": 2e-4,

    "num_train_epochs": 1,

    "logging_steps": 10,

    "save_steps": 50,

    "save_total_limit": 2,

    "report_to": "none"

}


# CREATE TRAINING ARGUMENTS

training_args = TrainingArguments(
    **training_settings
)


# SAVE CONFIGURATION

os.makedirs(OUTPUT_DIR, exist_ok=True)

lora_config.save_pretrained(OUTPUT_DIR)

with open(
    os.path.join(OUTPUT_DIR, "training_settings.json"),
    "w"
) as file:

    json.dump(training_settings, file, indent=4)


# DISPLAY CONFIGURATION

print("\n========== LORA CONFIGURATION ==========")

print("Model:", MODEL_NAME)

print("LoRA Rank:", lora_config.r)

print("LoRA Alpha:", lora_config.lora_alpha)

print("LoRA Dropout:", lora_config.lora_dropout)

print("Target Modules:", lora_config.target_modules)

print("Task Type:", lora_config.task_type)

print("\n========== TRAINING CONFIGURATION ==========")

print("Batch Size:", training_args.per_device_train_batch_size)

print(
    "Gradient Accumulation:",
    training_args.gradient_accumulation_steps
)

print("Learning Rate:", training_args.learning_rate)

print("Epochs:", training_args.num_train_epochs)

print("\nConfiguration saved successfully!")

print("Output directory:", OUTPUT_DIR)
```

---

# 9. Understanding Training Hyperparameters

## Batch Size

```python
per_device_train_batch_size = 1
```

Number of training examples processed per device in one training step.

## Gradient Accumulation

```python
gradient_accumulation_steps = 4
```

Accumulates gradients over multiple steps before performing an optimizer update.

With a batch size of 1 and accumulation steps of 4, the effective batch size is 4 for a single device.

## Learning Rate

```python
learning_rate = 2e-4
```

Controls the magnitude of parameter updates during training.

## Number of Epochs

```python
num_train_epochs = 1
```

One epoch means processing the complete training dataset once.

These are initial experimental settings, not universally optimal values.
