## 1. LEARN — Storytelling (30 minutes)

Technical storytelling explains a project in a clear sequence: problem, approach, implementation, evidence, and limitations.

### Your project's story

1. **Problem:** A general LLM may not know the specific information in a user's documents.
2. **Approach:** Retrieve relevant passages from a knowledge base and provide them to the LLM as context.
3. **Pipeline:** Ingest documents, create embeddings, retrieve candidate chunks, rerank them, and generate an answer.
4. **Evidence:** Test with questions that are answerable from the corpus and questions that are not.
5. **Limitations:** Explain where retrieval or generation can fail and what remains to improve.

### A short project explanation

> I built a Retrieval-Augmented Generation application that answers questions using a supplied knowledge base. Documents are chunked and embedded, stored in ChromaDB, retrieved through semantic search, and reranked with a cross-encoder. The selected passages are sent to Gemini, which generates a streamed response through a FastAPI backend to a React frontend. I test it with answerable and unanswerable questions to assess retrieval, grounding, and failure handling.

Adjust this description if any part is not implemented in your current code.

A convincing demo should show a real question, a source-supported answer, an unanswerable question, and the system's response when information is missing. Do not describe an intended feature as completed unless you have tested it.

### Step 4 — Run end-to-end questions
