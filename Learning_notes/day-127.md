# Day 127 — Add a Reranking Step

## Objective

Learn why reranking helps retrieval and add a reranking step to the RAG retrieval pipeline.

## What Is Reranking?

Reranking is a second ranking step applied after the initial retrieval stage.

The first retriever quickly finds a group of potentially relevant documents. A reranker then examines those candidates again and puts the most relevant documents first.

The basic idea is:

```text
Retrieve broadly → Rerank carefully → Keep the best results
```

## Why Does Reranking Help?

A retriever is designed to be fast. It may return several relevant or partially relevant documents, but the order is not always perfect.

For example, suppose we retrieve 10 candidates:

```text
1. Relevant
2. Somewhat relevant
3. Relevant
4. Not very relevant
5. Very relevant
...
```

The best document might be lower in the initial results.

Instead of immediately keeping only the top 3, we can retrieve more candidates, rerank them, and then keep the best 3.

```text
Retrieve 10
     ↓
Rerank 10
     ↓
Keep best 3
```

## Retrieval vs Reranking

### Retrieval

Retrieval is the first stage. It quickly finds possible candidates.

```text
Question
   ↓
Embedding / Hybrid Search
   ↓
Candidate Documents
```

The goal is to avoid missing useful information.

### Reranking

Reranking is the second stage. It improves the ordering of the candidates.

```text
Candidate Documents
       ↓
    Reranker
       ↓
Better ordered Documents
```

The goal is to put the most relevant information first.

## Simple Example

Question:

```text
What technology allows computers to learn patterns from data?
```

Initial retrieval might return:

```text
1. Artificial intelligence enables computer systems...
2. Deep learning uses neural networks...
3. Machine learning allows computers to learn patterns from data...
4. Python is a programming language...
```

After reranking, the order could become:

```text
1. Machine learning allows computers to learn patterns from data.
2. Deep learning is a branch of machine learning...
3. Artificial intelligence enables computer systems...
4. Python is a programming language...
```

The strongest result is now at the top.

## Two-Stage Retrieval

Reranking creates a two-stage retrieval process:

```text
Stage 1
Question
   ↓
Fast Retrieval
   ↓
Candidate Documents

Stage 2
Candidate Documents
   ↓
Reranking
   ↓
Best Documents
```

This is useful because the two stages have different jobs:

- Retrieval finds a broad set of possible candidates.
- Reranking improves the order of those candidates.

## How It Fits Into the RAG Pipeline

The retrieval pipeline is becoming:

```text
User Question
      ↓
Multi-Query
      ↓
Hybrid Retrieval
      ↓
Candidate Documents
      ↓
Reranking
      ↓
Best Documents
      ↓
Context
      ↓
LLM
      ↓
Answer
```

Reranking therefore sits between initial retrieval and the final context sent to the LLM.

## Today's Build

The basic implementation idea is:

```python
results = retrieve(query, k=10)

reranked_results = rerank(query, results)

final_results = reranked_results[:3]
```

The important part is that we retrieve more candidates first and then select the best results after reranking.

## Important Concept

Reranking does not replace retrieval.

It works **after retrieval**.

Think of it as:

```text
Retrieval = Find candidates
Reranking = Order candidates
```

## What I Learned Today

- Reranking is a second ranking stage after retrieval.
- Retrieval should find a broad set of possible candidates.
- Reranking improves the order of those candidates.
- Retrieving more candidates before reranking can reduce the chance of missing useful information.
- Only the best reranked results need to be passed into the RAG context.
- Reranking improves the retrieval stage of the RAG pipeline.
